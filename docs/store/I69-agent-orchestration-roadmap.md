## 1 范围

### 1.0 阶段目标

**目标**：交付一个 **ComfyUI / n8n 形态的编排界面**——在画布上以「一个节点 = 一次 agent 调用（一次 turn）」编排后端 agent 调用；节点可拖拽 / 连线 / 保存（非法图在保存期被拒并定位），运行态只读叠加在同一张画布上。

| 段 | 内容 | 归属 |
|---|---|---|
| **前置段** | 模板 schema（R1）、run 台账与 run 事件（R2 / R4）、前端接缝（R5） | 本文件 R0–R5 |
| **界面段（目标本体）** | 可编辑编排画布（W3 模板编辑器）+ 运行态只读叠加（W4） | 下游规格 |

> **边界**：本阶段波次只交付「让该界面可编辑、可运行、可读」的前置，不交付界面形态本身。W3 的前置是 R1 冻结的模板 schema（读取与保存另需 R4 的模板命令）；W4 的前置是 W3 + R4 / R5 的契约与接缝。界面可用登记为 DoD7（§1.1），是阶段目标达成的最后一条；其形态与验收由下游规格定义，本文只登记前置与 DoD7。

### 1.1 阶段完成判据

| # | 判据 | 可判形式 |
|---|---|---|
| **DoD1** | 并行分支可用 | 同一 run 内不同会话的节点真实重叠推进 |
| **DoD2** | 条件路由可用 | 边条件按 turn 终态激活下游，未激活的标跳过 |
| **DoD3** | 图级 HITL 可用 | run 停在等待态，人工解决后继续，无默认超时 |
| **DoD4** | run 是业务事实 | 重启可读、可审计、run 级取消幂等、成本可按节点归因 |
| **DoD5** | 前端可读 | 断开重连后与台账一致，漏事件可校正 |
| **DoD6** | 零回归 | 无 run 时既有 chat / agent 单轮链路行为不变 |
| **DoD7** | 编排界面可用 | 画布上可编辑模板（拖拽 / 连线 / 保存，非法图保存期被拒并定位）；只读叠加 run 与节点状态；断开重连后与台账一致 |

> **交付按单元计，不按「七条全绿」计**（§1.4）：本表是**能力清单**，不是一次性闸门。任一交付单元（DU）满足 §1.4 的自证条件即可独立交付，交付状态与「已交付 / 覆盖 DoD / 未覆盖 DoD」登记在本文 §1.4.6 的 DU 台账（**不进 [I38 §2](./I38-agent-roadmap.md)**：I38 只记阶段级结论）。P18 整体标 ✅ 只在 DoD1–DoD7 **全部被某个已交付 DU 覆盖**时成立，此时才回写 [I38 §2](./I38-agent-roadmap.md) 一行；否则 I38 保持原状态不动，缺哪几条 DoD 只看 §1.4.6 台账。

### 1.2 波次表定义与路线

#### 1.2.1 本文的阶段表叫什么、只写什么

**名称**：本文的阶段表称「**波次表**」，唯一实体在 §3（下称「§3 波次表」）。它是 P18 唯一的波次台账；§4 是它的逐波展开，§6 是它退出条件的镜像，二者都不另立第二张表。

**波次编号**：前置段 `R0–R5`（本阶段交付），界面段 `W3–W4`（阶段目标本体，形态归下游规格）。跨文档引用写「P18-R3」，避免与 I38 的 `P0–P18` 混淆（§8 第 3 条）。

**只写这 6 列**：

| 列 | 写什么 | 粒度上限 |
|---|---|---|
| 波次 | 编号 + 名称 | 一行一个波次，编号不复用 |
| 目标 | 该波交付的能力 | 一句话，不写实现方案 |
| 前置 | 开工前必须已关闭的波次 | 波次编号或「无」 |
| 关闭缺口 | 该波关闭的 G 编号 | 只引用 §3.1 已登记的缺口 |
| 契约影响 | 是否动 wire | 只有「零」与「一次性出齐」两种取值 |
| 退出条件 | 该波完成判据 | 每条一句、可判通过 / 不通过，细则在 §4 展开 |

归属（本文件 / 下游规格）不逐行写，由 §1.2.2 的分段表承担：R0–R5 归本文件，W3–W4 归下游规格。

**不写这 5 类**：① 规格内部条款编号与判据细则（INV / A / K / UI 等，归下游规格）；② 代码文件清单与实现步骤（归 §4）；③ 进度与勾选（阶段级由本文自行判定、整体完成时回写 [I38 §2](./I38-agent-roadmap.md) 一条，DU 级归 §1.4.6，任务级归 tasklist）；④ 设计理由与取舍（归下游规格）；⑤「待立项 / 未立项 / 规格待补」这类悬空声明（见头部条款）。

#### 1.2.2 路线

**一句话**：立骨架（R0）→ 冻结模板（R1）→ 让 run 成为业务事实（R2）→ 解锁并行与条件路由（R3）→ 一次出齐 HITL / 预算 / 契约（R4）→ 让前端读得对（R5）→ 界面段先编辑（W3）后叠加（W4）。

| 步 | 波次 | 交付能力 | 做完能看到 |
|---|---|---|---|
| 1 | R0 | 独立 crate + 控制端口 + 内存台账，串行推进 | 两个 `turn` 节点按顺序跑完，节点状态与 turn 终态一致 |
| 2 | R1 | 模板 v1 与保存期校验 | 十类非法图在保存时被拒，并定位到节点 / 边 / 分组；`hitl` 的 `always` 被拒；版本不等拒绝加载 |
| 3 | R2 | 三张表 + 发起幂等 + 孤儿扫描 | 重启后 run / 节点 run / 模板都可读；重复发起不双执行 |
| 4 | R3 | 并发键 + 取消树 + 条件边 + 并行上限 | 不同会话的节点真实并行且不超上限；条件边只激活一条 |
| 5 | R4 | `hitl` + 预算归因 + 契约一次出齐 | run 停在等待态并可解决；无前端 run 仍完整推进 |
| 6 | R5 | 前端接缝与断线补齐 | 断开重连后前端状态与台账一致 |
| 7 | W3 | 可编辑编排画布（下游规格） | 画布上拖拽 / 连线 / 保存模板 |
| 8 | W4 | 运行态只读叠加（下游规格） | 同一画布只读显示 run 与节点状态 |

> 上表是路线导读，不新增判据；判据以 §3 波次表的退出条件为准。

**分段**：R0–R5 是前置段，全部在本文件闭环；W3–W4 是界面段（阶段目标本体），前置由本文件关闭、形态由下游规格定义（§1.0）。

**串行为什么不可省**：R1 依赖 R0 的最小模板作为反例来源；R2 必须按 R1 冻结的 schema 建表；R3 复用 R2 的台账；R4 的 `hitl` 复用 R3 的 run 状态机；R5 只消费 R4 冻结的契约。跳过任一前置，后续波次都要带返工（§7 风险 1 / 7）。

| 段 | 波次 | 交付面 |
|---|---|---|
| 编排内核 | R0–R3 | 独立 crate、控制端口、模板 schema、持久化、并行与条件路由 |
| 对外契约 | R4 | DTO、命令、run 事件、`hitl` 与预算 |
| 前端接缝 | R5 | 命令封装、事件唯一订阅、键控投影、重连补齐 |
| 界面段 | W3–W4 | 可编辑编排画布、运行态只读叠加（阶段目标本体，见 §1.0） |

> **现状（2026-11-22）**：`src/features/orchestration/` 已存在并注册为独立页面（路由 `/agent-orchestration`），当前是画布占位（内置预设 + 示例卡片放置，纯前端数据、无后端）。编排已从观测页移除，观测页只做只读观测。R5 在该占位之上收敛为接缝，不新增画布能力；界面段（W3 / W4）在该占位与 R5 接缝之上继续，本阶段只负责其前置冻结。

### 1.4 交付单元与交付方式

**为什么需要这一节**：§1.1 的 DoD 是「整个阶段做成什么才算成立」的能力清单；按七条全绿作为唯一闸门，会让已经能用的能力被压在一个未开工的界面段后面。本节把交付切成**可独立验收的功能实现**，让每一块能力做完就能交付，同时不放宽任何一条既有约束。

**DU 不是第二张波次表**：§3 波次表仍是唯一顺序来源，DU 不排顺序、不改前置、不改退出条件，只声明「哪一块能力做完时按什么验收、覆盖哪几条 DoD」。DU 与波次是多对一（一个 DU 落在一波内，不跨波拼接）。

**交付记录分三层，互不越界**：

| 层 | 落点 | 写什么 | 不写什么 |
|---|---|---|---|
| DU 定义与规则 | 本文 §1.4.1–§1.4.5 | DU 切分、自证条件、总结必备项 | 交付结果 |
| DU 交付结果 | 本文 §1.4.6 台账 | 每个 DU 的已交付 / 未交付、覆盖与未覆盖的 DoD、总结位置 | 任务明细、阶段结论 |
| 阶段级结论 | [I38 §2](./I38-agent-roadmap.md) P18 行 | 整体完成时回写一次：一句话结论 + 日期 | **不登记任何 DU 明细、不设门禁行** |

下游规格（含界面段规格）只提供**验收细则**，不得自行宣布「已交付」「已覆盖某条 DoD」或「阶段完成」——它们能做的只是让本节的某条自证条件可判通过或不通过。

#### 1.4.1 交付单元（DU）

**定义**：一个 DU = **一份可独立交付的功能实现**，须同时满足三条：① 落在 §3 波次表已登记的某一波内（前置段 R0–R5，或 §1.0 登记的界面段 W3–W4）；② 有该 DU 自己的可判验收结论；③ 可独立回退，回退不使已交付 DU 失效。

| DU | 波次 | 功能实现（一句话） | 覆盖 DoD |
|---|---|---|---|
| **DU1** | R0 | 编排内核骨架：串行 run 能跑完，turn 只经宿主控制端口发起 | —（DoD6 见 §1.4.3 第 5 条） |
| **DU2** | R1 | 模板 schema 与保存期校验：合法模板可定义，非法图保存期被拒并定位 | — |
| **DU3** | R2 | run 台账与持久化：模板 / run / node_run 落库，重启可读 | DoD4（部分：重启可读、可审计） |
| **DU4** | R3 | 并行与条件路由：跨会话并行、条件边、取消树、并行上限 | DoD1 / DoD2 / DoD4（部分：取消幂等） |
| **DU5** | R4 | 图级 HITL、预算与 wire 冻结：run 可停在等待态、成本可归因、契约一次出齐 | DoD3 / DoD4（至此完整） |
| **DU6** | R5 | 前端接缝：命令封装、事件唯一订阅、键控投影、重连补齐 | DoD5 |
| **DU7** | W3–W4 | 界面段：可编辑编排画布 + 运行态只读叠加 | DoD7 |

> DoD4 的四个子项按字面拆到 DU3 / DU4 / DU5，**不新增判据**；DoD4 只有在其四个子项全部被已交付 DU 覆盖时才算满足。
>
> DU1 / DU2 不直接覆盖任何 DoD（它们是后续 DU 的前置），交付时只按 §1.4.3 自证；「不覆盖 DoD」不等于「不可交付」。

#### 1.4.2 灵活性（可以怎么交付）

| 可以 | 说明 |
|---|---|
| 分批交付 | 只交付 DU1–DU3 即可停：得到「可持久化的串行编排」，DoD4 部分满足，其余显式登记为未覆盖 |
| 跳段交付 | 依赖图允许的前提下，跳过当前不需要的能力（如先不做界面段 DU7），不影响已交付 DU 可用 |
| 合并交付 | 多个 DU 同批交付（如 DU4 + DU5 一次验收），按最严的那条自证条件执行 |
| 分批合入 | 同一 DU 内允许按子项多次合入主干，但验收以 DU 为单位一次完成，不做「半 DU 验收」 |
| 交付形式灵活 | 交付物是一份**功能实现总结**（§1.4.5），不需要等全阶段收口，也不需要先补齐所有文档形态 |

#### 1.4.3 自证条件（每个 DU 交付时必须全部满足）

| # | 条件 | 判据 |
|---|---|---|
| 1 | 退出条件全绿 | DU1–DU6：该 DU 所在波次的 §4 退出条件逐条通过。DU7：DoD7 的三条可判形式通过（细则由界面段规格提供，本文不引用其编号） |
| 2 | 共性门禁 | C7：编译 / 测试 / lint / 契约检查全绿、无新增警告、验证资产随交付物同波完成 |
| 3 | 契约纪律 | C5 / C8：DU1–DU4 零契约 diff；DU5 一次出齐；冻结后不再就地追加 |
| 4 | 唯一执行路径 | C2：交付后全仓仍无第二个 turn 发射点 |
| 5 | 零回归（DoD6） | 无 run 时既有 chat / agent 单轮链路行为不变；**且已交付 DU 的退出条件在本 DU 交付后仍全绿** |
| 6 | 可回退 | C9：回退只下线代码路径、保留已落库数据；删表单列并登记为不可逆动作 |

#### 1.4.4 灵活性边界（不可放宽的）

| 不可 | 依据 |
|---|---|
| DU 跨波次拼接 | C1（每波独立可验收）；一个 DU 只能落在一波内 |
| 借交付灵活性新开 / 合并波次 | §8 第 2 条；波次变更只走该条流程 |
| 跳过 C2 / C5 / C8 / C9 | §2 波次约束；DU 只是交付单位，不是豁免单位 |
| 未交付 DU 默认视为完成、未覆盖的 DoD 默认标满足 | §1.1 注释段；登记必须显式留空 |
| 把 DU 拆到无法验收 | §1.4.1 定义第 ② 条：每个 DU 至少覆盖一条可判退出条件 |
| 用 DU 改写 §3 / §4 的前置与退出条件 | §1.2.1；DU 不排波次 |

#### 1.4.5 功能实现总结（交付记录必备 5 条）

1. **DU 编号与覆盖波次**（如「DU3 / R2」）；
2. **能力一句话 + 演示方式**（怎么看到它工作，不写实现步骤）；
3. **覆盖的 DoD 逐条 + 未覆盖的 DoD 逐条**（未覆盖项显式留空，写「本 DU 不覆盖」）；
4. **自证条件逐条结论**（§1.4.3 六条，逐条写通过 / 不通过及依据）；
5. **回退点与已落库数据处置**（回退到哪、数据留或删、删表是否登记为不可逆）。

> 这份总结按 DU 归档在 tasklist（或随交付的说明），并在 §1.4.6 台账登记「已交付 / 覆盖 DoD / 未覆盖 DoD / 总结位置」三项；**交付是否成立只看本节的六条自证条件与 §1.4.6 的登记，不看任何下游规格的自我结论，也不写进 [I38 §2](./I38-agent-roadmap.md)**。

**填写规则**：

1. 「状态」只有两值：`未交付` / `已交付`；`已交付` 必须同时填交付日期与总结位置。
2. 「未覆盖 DoD」逐条列出，不写区间、不省略；未交付 DU 的「覆盖 DoD」写 `—`，不得留空让读者猜。

5. 回退一个 DU 时把该行改回 `未交付` 并在「未覆盖 DoD」恢复原值，已落库数据处置写进总结（C9）。

### 4.4 R3 并行、取消树与条件路由

| 项 | 内容 |
|---|---|
| 目标 | 交付分析 §4.12 价值门槛的前两项：**并行分支**（含并行上限闸门）与**条件路由** |
| 交付物 | ① 并发键 `(run_id, node_id)` 与就绪集合推进；② run 级取消树（run → 节点 → turn），幂等；③ 条件边求值（只读 turn 终态，闭集 `always` / `onSuccess` / `onFailure`）；④ 冲突域判据（同工作区写节点不得并行）；⑤ 会话互斥守门：同一会话同一时刻最多一个运行中节点；⑥ 并行上限闸门（同时 `running` 节点数封顶，超出就绪节点排队，缺省上限 4） |

| 前置 | R2 |
| 退出条件 | ① 两个不同会话的节点并行推进，墙钟明显重叠；② 同一会话的并行请求被守门拒绝或串行化，不出现双 turn；③ 取消 run 使全部在跑节点收到取消，重复取消无副作用；④ 条件边只激活一条下游，其余标跳过且语义是调度阻断；⑤ 同工作区写节点不并行；⑥ 同时 `running` 节点数不超过并行上限，超出部分留在就绪集合排队（不丢节点、不标失败） |
| 回退点 | 回退到串行只需改调度模块，台账与 schema 不动；已落库数据保留 |

| 不交付 | 前端接缝（R5）、画布渲染（§1.3） |
| 前置 | R3 |
| 退出条件 | ① `hitl` run 停在等待态，解决后继续且回答只进台账；② gate 无默认超时，只有显式取消或解决能结束等待；③ run 预算耗尽按预算失败收口且账目可按节点分摊；④ 契约生成与校验幂等、绑定清单登记齐全；⑤ 前端未接入时 run 仍完整推进；⑥ 宿主侧校正可补齐台账 |
| 回退点 | DTO 与命令可整体移除（不删台账、不删模板数据）；事件是广播，无订阅者即无影响 |

### 4.6 R5 前端接缝与断线补齐

| 项 | 内容 |
|---|---|
| 目标 | 让前端能**正确读到** run 与节点状态，并在漏事件后自愈；不做任何画布呈现 |
| 交付物 | ① 命令封装（统一经 `tauriInvoke`）；② 全仓唯一事件订阅入口；③ 按 `(runId, nodeId)` 键控投影；④ 重连流程：先全量读、再事件增量、漏事件调校正；⑤ 模块注册（只留入口与空态） |
| 不交付 | 画布节点渲染、模板编辑器、运行态叠加、任何新 DTO / 命令 / 事件 |
| 前置 | R4 |
| 退出条件 | ① 断开重连后状态与台账一致；② 命令封装与事件订阅各自唯一入口，组件不直接调用底层 `invoke` / `listen`；③ 投影按键控而非单缓冲 |
| 回退点 | 整个 `src/features/orchestration/` 删除即可回退；后端、契约与数据不动 |

## 5 依赖与并行

```
R0 ──→ R1 ──→ R2 ──→ R3 ──→ R4 ──→ R5

R1 ─────────────────────────────→ W3 本地编辑（模板 schema 输入）
R4 ─────────────────────────────→ W3 读取与保存（模板命令）
R5 ─────────────────────────────→ W4 运行态叠加（W3 之后）
```

| 关系 | 说明 |
|---|---|
| R0 → R1 | schema 需要先有「能跑的最小模板」作为反例来源 |
| R1 → R2 | 持久化必须按已冻结的 schema 建表 |
| R3 → R4 | HITL 的等待态复用 R3 的 run 状态机 |
| R4 → R5 | R5 只消费 R4 冻结的契约，不反向影响 R4 |
| R1 / R4 → W3 · R5 → W4 | 界面段前置：W3 的本地编辑只读 R1 冻结的模板 schema，读取与保存另需 R4 的模板命令；W4 读 W3 + R4 / R5 的契约与接缝。界面段波次与形态由下游规格定义，不在 §3 / §4 登记 |
| R0–R5 ↔ W1 / W2 | **可并行**：W1 / W2 是前端设施与示例内容，不读模板 schema、不读 run 台账 |
| P18 ↔ P8.2 / P8.3 | 分层不同（L2 vs L3），互不前置 |
| P18 ↔ 在途阶段 | P14 的改动面为 `assistant-tools` / `tool_setup.rs` / 前端模式预置，与本阶段无文件交叠；若后续阶段占用 `cmd/agent/mod.rs`，以先合入者为准，后合入方重跑 R0 退出条件 |

## 7 风险与回退

### 7.1 风险

| # | 风险 | 触发点 | 复核波次 | 处置 |
|---|---|---|---|---|
| 1 | schema 返工 | R1 冻结后发现参数面不够 | R2 开工前 | R1 与 R2 之间是唯一免费窗口；R2 之后改 schema 必须带迁移并保持旧行可读 |
| 2 | 事件丢失导致 run 挂死 | tap 丢事件 / 进程被杀 | R0、R4 | 只降级为「停在最后已知节点」，靠启动扫描（R2）与校正（R4 / R5）收口，**不得**让 turn 失败 |
| 3 | 会话互斥被当成并行障碍 | R3 发现同会话并行不可行 | R3 开工前 | 如实收缩为「并行需不同会话」，不引入第二套 turn 键 |
| 4 | 孤儿扫描误判 | 启动扫描把正在跑的 run 标死 | R2 | 只处理「台账在跑但无活跃 turn」；活跃判定必须来自会话互斥表而非时间戳 |
| 5 | 预算口径漂移 | R4 引入 run 预算 | R4 | 沿用「未配置 ≠ 0」；run 预算与 turn 预算各自独立，不做乘法换算 |
| 6 | 下游提前绑定未冻结的 schema | 模板编辑器与 R2–R5 并行开工 | R1 验收后 | R1 冻结前不对下游作承诺；冻结后 schema 变更走新波次，不就地改 |
| 7 | 契约冻结后仍缺字段 | R5 接入时发现契约不足 | R5 开工首日 | 不就地追加；按 C8 新开一波，或按 §7.2 回退到 R4 重冻结 |
