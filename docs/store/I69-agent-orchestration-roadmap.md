## 1 范围

### 1.1 阶段完成判据

| # | 判据 | 可判形式 |
|---|---|---|
| **DoD1** | 并行分支可用 | 同一 run 内不同会话的节点真实重叠推进 |
| **DoD2** | 条件路由可用 | 边条件按 turn 终态激活下游，未激活的标跳过 |
| **DoD3** | 图级 HITL 可用 | run 停在等待态，人工解决后继续，无默认超时 |
| **DoD4** | run 是业务事实 | 重启可读、可审计、run 级取消幂等、成本可按节点归因 |
| **DoD5** | 前端可读 | 断开重连后与台账一致，漏事件可校正 |
| **DoD6** | 零回归 | 无 run 时既有 chat / agent 单轮链路行为不变 |

> DoD1–DoD3 是分析 §4.12 的三项价值门槛：缺任一项，本阶段只等价于既有机制的重新组合。DoD1–DoD6 全满足才可标 P18 完成；否则在 [I38 §2](./I38-agent-roadmap.md) 标「部分交付」并写明缺哪几条。

### 1.2 波次链与交付面

**波次链**：`R0 → R1 → R2 → R3 → R4 → R5`，五波后端 + 一波前端接缝，串行推进。

| 段 | 波次 | 交付面 |
|---|---|---|
| 编排内核 | R0–R3 | 独立 crate、控制端口、模板 schema、持久化、并行与条件路由 |
| 对外契约 | R4 | DTO、命令、run 事件、`hitl` 与预算 |
| 前端接缝 | R5 | 命令封装、事件唯一订阅、键控投影、重连补齐 |

> **现状（2026-11-22）**：`src/features/orchestration/` 已存在并注册为独立页面（路由 `/agent-orchestration`），当前是画布占位（内置预设 + 示例卡片放置，纯前端数据、无后端）。编排已从观测页移除，观测页只做只读观测。R5 在该占位之上收敛为接缝，不新增画布能力。

### 1.3 范围外与对下游的交付承诺

| 项 | 处置 | 对下游的承诺 |
|---|---|---|
| 模板编辑器 | 不在本阶段 | R1 的模板 schema 是它的输入契约；schema 变更只在 R1 内发生并通知下游，本阶段不替下游改形态 |
| 运行态叠加 | 不在本阶段 | R5 的接缝（命令封装 / 事件订阅 / 键控投影）是它的输入契约 |
| 画布设施与预设 | W1 / W2（I66 / I68，已交付） | 本阶段只叠加，不改设施 |
| L3 跨会话 Router | P8.2 / P8.3 | 分层不同（L2 vs L3），互不前置 |
| 子代理委派节点 | P8.1（暂缓） | 本阶段不提供该节点类别 |
| 后台任务（关应用后继续跑） | P9 / I52-Ext | 本阶段不承诺该能力 |
| 图级授权、结果缓存、图级环、typed handoff、变量池、队列、节点级续跑、工具调用节点、原始事件落库、运行时注入节点 | 一律不进入任何波次 | 模板 schema 不为这些预留字段 |

## 2 波次约束

| # | 约束 | 在哪一波可判 |
|---|---|---|
| C1 | 每波独立可验收：可编译、可测、可回退，不依赖下一波 | 每波退出条件 |
| C2 | 任何波次不得交付第二条执行路径：turn 只能经宿主控制端口发起 | R0 退出条件② |

| C4 | 后端早于前端 | R4 先于 R5 |

## 4 每波详述

### 4.1 R0 骨架与归属键

| 项 | 内容 |
|---|---|
| 目标 | 让「编排层能驱动一次串行 run 并读到 turn 终态」这件事在无持久化、无 wire、无前端的情况下成立 |
| 交付物 | ① `crates/assistant-orchestrator`（模板模型 / 控制端口 / 调度 / run 状态机 / 台账 / 事件骨架）；② 宿主控制端口 trait（发起 turn / 取消会话 / 等待 turn 终态）；③ 内存台账；④ 最小模板（2–3 个 `turn` 节点 + 顺序边）；⑤ 宿主侧发起 turn 回传 `turn_id` / `assistant_message_id` / `turn_index`，并组合事件 tap |
| 不交付 | 落库、并行、条件边、HITL、预算、任何 DTO / 命令 / 事件 |
| 前置 | 无波次前置。**开工检查**：① 建立 P18 tasklist 并登记 R0–R5；② 记录契约基线（`npm run contract:check` 幂等）作为零 diff 起点；③ 确认改动面 `src-tauri/src/cmd/agent/mod.rs` 与在途阶段无文件交叠，有交叠先对齐合入顺序 |
| 退出条件 | ① 两节点串行 run 跑完且节点状态正确；② 全仓无第二个 turn 发射点；③ crate 依赖图无宿主 / UI 框架；④ 宿主拒绝并发时节点标失败、run 不挂死；⑤ 编排层 panic 不影响 turn 终态；⑥ 契约文件零 diff |
| 回退点 | 整个 crate 删除即可回退；无 schema、无 wire、无迁移 |

### 4.2 R1 模板 schema v1 与保存期校验

| 项 | 内容 |
|---|---|
| 目标 | 把「工作流模板」从 R0 的最小结构冻结成有版本、有校验、可判非法的数据 |
| 交付物 | ① 模板 v1（`id` / `name` / `version` / 语义字段（节点、边）/ 呈现字段（布局），语义与坐标分列）；② 节点类别闭集 `turn` / `hitl`；③ 节点参数结构（常量参数，不接受引用）；④ 边条件闭集 `always` / `onSuccess` / `onFailure`；⑤ 保存期校验（环、悬空边、重复 id、必填参数、未知类别、条件与类别匹配）；⑥ 校验错误定位到节点 / 边 |
| 不交付 | 落库、编辑器 UI、参数表单、typed handoff |
| 前置 | R0 |
| 退出条件 | ① 六类非法图各被拒且定位到元素；② 合法图通过；③ 环在保存期被拒，不是运行期才炸；④ 改坐标不改变任何校验结果；⑤ 未知节点类别被拒，不降级为默认态 |
| 回退点 | schema 只存在于 crate 内部与内存，未落库 → 改结构零迁移成本；下游尚未开工，无外部依赖 |

### 4.3 R2 持久化与崩溃收口

| 项 | 内容 |
|---|---|
| 目标 | run 与节点结果引用成为**业务事实**，重启后仍可读、可审计，且不阻塞既有会话删除 |
| 交付物 | ① 三张表（模板 / run / 节点 run）；② 存储层模块与迁移；③ 落库版台账；④ 发起幂等（同一模板 + 来源会话 + 客户端 run 键重复发起返回既有 run）；⑤ 启动扫描收口孤儿 run |
| 不交付 | 原始事件落库、节点级续跑、run 归档与清理策略 |
| 前置 | R1 |
| 退出条件 | ① 重启后 run / 节点 run 可读且状态一致；② 重复发起不双执行；③ 进程被杀后孤儿 run 被启动扫描收口；④ 删除会话不因台账失败，悬空引用按已删除呈现；⑤ 台账写失败不回滚 turn，run 标失败并注明原因 |
| 回退点 | 代码路径可整体下线（删模块 + 停写）；**已落库数据默认保留**，删表按 C9 登记为不可逆动作；既有会话与消息表未改结构 |

### 4.4 R3 并行、取消树与条件路由

| 项 | 内容 |
|---|---|
| 目标 | 交付分析 §4.12 价值门槛的前两项：**并行分支**与**条件路由** |
| 交付物 | ① 并发键 `(run_id, node_id)` 与就绪集合推进；② run 级取消树（run → 节点 → turn），幂等；③ 条件边求值（只读 turn 终态，闭集 `always` / `onSuccess` / `onFailure`）；④ 冲突域判据（同工作区写节点不得并行）；⑤ 会话互斥守门：同一会话同一时刻最多一个运行中节点 |
| 不交付 | 会话内并行（受既有互斥表约束）、条件表达式语言（不做求值器）、typed handoff |
| 前置 | R2 |
| 退出条件 | ① 两个不同会话的节点并行推进，墙钟明显重叠；② 同一会话的并行请求被守门拒绝或串行化，不出现双 turn；③ 取消 run 使全部在跑节点收到取消，重复取消无副作用；④ 条件边只激活一条下游，其余标跳过且语义是调度阻断；⑤ 同工作区写节点不并行 |
| 回退点 | 回退到串行只需改调度模块，台账与 schema 不动；已落库数据保留 |

### 4.5 R4 HITL、预算归因与对外契约

| 项 | 内容 |
|---|---|
| 目标 | 交付价值门槛第三项（**人在环节点**）+ 预算分层，并把整个阶段一次性暴露为契约 |
| 交付物 | ① `hitl` 节点与 gate 状态机；② run 墙钟 / 节点数上限（可执行闸门）+ token 归因（只读）；③ 契约 DTO；④ 命令面；⑤ run 事件广播 |
| 波内顺序 | 契约类型 → 命令 → 事件 → 生成物 → 绑定登记，一次性完成（C8）；顺序颠倒会留下半冻结的契约面 |
| 不交付 | 前端接缝（R5）、画布渲染（§1.3） |
| 前置 | R3 |
| 退出条件 | ① `hitl` run 停在等待态，解决后继续且回答只进台账；② gate 无默认超时，只有显式取消或解决能结束等待；③ run 预算耗尽按预算失败收口且账目可按节点分摊；④ 契约生成与校验幂等、绑定清单登记齐全；⑤ 前端未接入时 run 仍完整推进；⑥ 宿主侧校正可补齐台账 |
| 回退点 | DTO 与命令可整体移除（不删台账、不删模板数据）；事件是广播，无订阅者即无影响 |

### 4.6 R5 前端接缝与断线补齐

| 项 | 内容 |
|---|---|
| 目标 | 让前端能**正确读到** run 与节点状态，并在漏事件后自愈；不做任何画布呈现 |
| 交付物 | ① 命令封装（统一经 `tauriInvoke`）；② 全仓唯一事件订阅入口；③ 按 `(runId, nodeId)` 键控投影；④ 重连流程：先全量读、再事件增量、漏事件调校正；⑤ 模块注册（只留入口与空态） |
| 不交付 | 画布节点渲染、模板编辑器、运行态叠加、任何新 DTO / 命令 / 事件 |
| 前置 | R4 |
| 退出条件 | ① 断开重连后状态与台账一致；② 命令封装与事件订阅各自唯一入口，组件不直接调用底层 `invoke` / `listen`；③ 投影按键控而非单缓冲 |
| 回退点 | 整个 `src/features/orchestration/` 删除即可回退；后端、契约与数据不动 |

## 5 依赖与并行

```
R0 ──→ R1 ──→ R2 ──→ R3 ──→ R4 ──→ R5

R1 ─────────────────────────────→ 模板编辑器（范围外；可与 R2–R5 并行）
R5 ─────────────────────────────→ 运行态叠加（范围外）
```

| 关系 | 说明 |
|---|---|
| R0 → R1 | schema 需要先有「能跑的最小模板」作为反例来源 |
| R1 → R2 | 持久化必须按已冻结的 schema 建表 |
| R3 → R4 | HITL 的等待态复用 R3 的 run 状态机 |
| R4 → R5 | R5 只消费 R4 冻结的契约，不反向影响 R4 |
| R0–R5 ↔ W1 / W2 | **可并行**：W1 / W2 是前端设施与示例内容，不读模板 schema、不读 run 台账 |

## 7 风险与回退

### 7.1 风险

| # | 风险 | 触发点 | 复核波次 | 处置 |
|---|---|---|---|---|
| 1 | schema 返工 | R1 冻结后发现参数面不够 | R2 开工前 | R1 与 R2 之间是唯一免费窗口；R2 之后改 schema 必须带迁移并保持旧行可读 |
| 2 | 事件丢失导致 run 挂死 | tap 丢事件 / 进程被杀 | R0、R4 | 只降级为「停在最后已知节点」，靠启动扫描（R2）与校正（R4 / R5）收口，**不得**让 turn 失败 |
| 3 | 会话互斥被当成并行障碍 | R3 发现同会话并行不可行 | R3 开工前 | 如实收缩为「并行需不同会话」，不引入第二套 turn 键 |
| 4 | 孤儿扫描误判 | 启动扫描把正在跑的 run 标死 | R2 | 只处理「台账在跑但无活跃 turn」；活跃判定必须来自会话互斥表而非时间戳 |
| 5 | 预算口径漂移 | R4 引入 run 预算 | R4 | 沿用「未配置 ≠ 0」；run 预算与 turn 预算各自独立，不做乘法换算 |
| 6 | 下游提前绑定未冻结的 schema | 模板编辑器与 R2–R5 并行开工 | R1 验收后 | R1 冻结前不对下游作承诺；冻结后 schema 变更走新波次，不就地改 |
| 7 | 契约冻结后仍缺字段 | R5 接入时发现契约不足 | R5 开工首日 | 不就地追加；按 C8 新开一波，或按 §7.2 回退到 R4 重冻结 |

### 7.2 回退触发与数据处置

| 触发情形 | 处置 |
|---|---|
| 退出条件在本波内无法满足，且根因在更早波次的交付物 | 回退到该波，不跨波并行修补 |

| 契约冻结后需改字段 | 回退到 R4 重冻结；R5 已交付部分按新契约重做 |
