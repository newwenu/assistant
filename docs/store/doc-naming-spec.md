# 文档命名规范

> 本文只规定 `docs/` 下文档的**文件名与标题**。文档类型怎么判、状态怎么标、索引怎么维护、归档怎么流转，都不在本文范围。
> 适用范围：`docs/` 全部子目录。

---

## 1 文件名公式

```
阶段 / 议题文档：  I{nn}[{a-z}]-{topic}-{suffix}.md
非编号文档：      {topic}-{suffix}.md
```

## 2 后缀

后缀表达**文档形态**。下表为常用词，够用就用；出现新形态再新增一个词，不要求全库统一。

| 后缀 | 形态 |
|---|---|
| `-spec` | 规格（阶段 / 主题 / 写作规范） |
| `-tasklist` | 任务清单（勾选与验收） |
| `-analysis` | 分析（参考、对照、缺口） |
| `-design` | 设计（方案与决策记录） |
| `-audit` | 审计（覆盖率 / 一致性核查） |
| `-inventory` | 现状盘点 |
| `-roadmap` | 路线图（阶段顺序与门禁） |
| `-architecture` | 架构盘点 |
| `-principle` | 原则（审查 / 拆分判据） |
| `-index` | 索引 |
| `-baseline` | 基线（能力对照矩阵） |
| `-attribution` | 归因（编译期来源说明） |
| `-devlog` | 开发日志 |
| `-guide` | 指南 |

约束：

- 后缀为 1–3 个英文词，kebab-case，取**形态名词**而非内容名词；多词时**最后一个词**定形态（`-conformance-spec` 归 spec）。
- 禁止把版本、日期、状态当后缀：`-v2`、`-final`、`-new`、`-old`、`-draft`、`-2026-11-22`。
- 禁止用后缀编码阶段或优先级：`-p14`、`-high`、`-next`。
- 表外的词只要仍属形态名词即可使用；出现明显同义分裂（如 `-review` / `-audit` 混用）时，收敛到表内已有词。

## 3 topic 与字符集

- `topic` 为 2–6 个英文词，kebab-case，只描述「管什么」。
- 禁止把版本、日期、状态写进文件名：`-v2`、`-final`、`-new`、`-old`、`-2026-11-22`。
- 文件名只允许 ASCII；禁止中文、空格、下划线。

## 4 编号

- `I{nn}` 是议题编号：全库唯一、递增、永不复用，文档归档后编号也不释放。
- 子字母 `{a-z}` 只表示「同一议题的拆分文档」，不得暗示阶段号。
- `P{nn}` 是实施阶段号，不进入文件名；`I` 与 `P` 的映射由所属轴 roadmap 维护。
- 非阶段文档（写作规范、现状盘点、实测记录、参考分析）不带 `I` 编号。
- 新编号 = 现存最大值 + 1；跳号需写明理由。

## 5 标题

```
# I{nn} — {中文标题}    编号文档
# {中文标题}             非编号文档
```

- 编号与标题之间是「空格 + em dash + 空格」，禁止 `# I71 Agent...` 这类无分隔写法。
- 标题不带状态、日期、「修订版」「草稿版」。
- 标题是唯一允许中文的位置；文件名仍须全 ASCII。

## 6 存量冻结

不改存量文件名：改名会打断全库引用，收益低于成本。确需改名时，一次性修正全部引用。

## 7 检查

新增与改名的文档须满足：

| 判据 |
|---|
| 符合 §1 公式，后缀是形态名词 |
| 后缀、`topic` 均无版本 / 日期 / 状态 / 阶段词 |
| 文件名为 ASCII，无中文、空格、下划线 |
| 编号唯一、递增，未复用已归档编号 |
| 标题符合 §5，带 ` — ` 分隔（编号文档） |
