## 1 目标与非目标

### 1.1 目标

1. 交付一个**可验收的边界**：可写根之外的写入必须失败、进程树必须可被整体回收、敏感目录不可读（后端实现与判据见 I53（已归档））；
2. 交付 `shell` 工具：`execute` 意图、命令级审批键、进程级超时、输出落盘与回读、结果可被模型纠错（工具规格见 [I56](../achievement/I56-shell-tool-spec.md)）；
3. 让审批卡片如实回答「这次执行被什么边界包着」（隔离强度 / 可写根 / 网络可达）；
4. 让 P10 的三个接入点有稳定事实源（`execute` 恒 `Ask` 的消费方、命令分类器、内核隔离已就绪）；
5. 全程 fail-closed：**不存在「探测失败就无沙箱执行」的路径**；
6. 让工具输出**可回读**：输出落到应用管理的同一存储，模型按引用路径回读，消除「落盘即失联」。

### 1.2 非目标

- 不新增命令字符串黑名单（§2.3：字符串匹配不是边界，禁止作为拦截依据）；
- 不替代审批：沙箱不改变 Policy / Gateway 的决策（§2.3、I56 §6）；
- 不做容器 / microVM / 内核驱动级后端（虚拟化层 L3+，见 §2.1），不做云端沙箱；
- 不做 `shell` 的交互式会话（PTY / stdin 注入 / 长驻进程），一次调用 = 一次执行；
- **不做后台任务**（异步执行 / 任务 id / 状态机 / 轮询回收）：发起点只能是 turn kernel 或 app supervisor——它们决定「一次工具调用何时算结束」与「进程归谁回收」，而 P14 的改动面是工具实现与审批链，这两处都不在其中。故不属 P14（与 P9 持久化运行同类）；运行期无进度见 I56 §15 OQ8，将来引入时的改动面见 [I52-Ext](./I52-ext-background-task.md)（未立项）；
- 不做命令级授权归一化（「同 `argv[0]` 合并键」是 S1 候选，见 I56 §15 OQ2）；
- 不开放跨会话输出读取：回读只作用于**本会话**输出命名空间（I56 §8.7）；
- 不改 I50 的 `AuditOutcome` 封闭词表（隔离强度走工具结果与审批卡，不进审计词表，I56 §10）。

### 1.3 与 `I38c §13`（已归档）恢复条件的对照

| 恢复条件 | 本阶段结论 |
|---|---|
| 具备真正的 OS 级隔离（而非仅字符串守卫） | **满足**：I53 §5（已归档）三个平台后端均为系统强制（Token+ACL / Landlock / Seatbelt） |
| 或具备结构化执行（不经过 shell 解释器） | **不采用**：模型需要的是通用命令能力；结构化执行会把能力砍到白名单，且仍无法限制子进程行为 |
| 或具备可验证的 dry-run | **部分满足**：`preview_for_approval` 只报「命令类别 + 隔离强度 + 规模未知」，不承诺 dry-run 语义（I56 §5.3） |

结论：本阶段满足条件 1，`shell` 可以恢复；条件 2 明确不采用并记录理由。

## 2 术语与分层（唯一出处）

### 2.1 两根轴：检测层 vs 虚拟化层

「L2 / L3 / L4」在本仓文档里被两套轴同时使用，必须写清是哪根轴：

| 轴 | 取值 | 出处 | 含义 |
|---|---|---|---|
| **检测层** | L2 字符串/规则匹配 → L3 解析后判定（`canonicalize` / argv）→ L4 内核强制 | I18 design §3.17.1（已归档）、[参考分析 §5.4](./agent-sandbox-reference-analysis.md) | 判定「这次操作到底碰了什么」的手段强度 |
| **虚拟化层** | L1 OS 原生虚拟化（Token+Job / Landlock / Seatbelt / bwrap）→ L2 LSM / seccomp → L3 用户态内核（gVisor）→ L4 硬件虚拟化 | 沙箱调研 §2–§7（已归档） | 隔离由谁提供 |

**约束**：本仓文档禁止裸写「L4 沙箱」，必须写「检测层 L4」或「虚拟化层 L1/L2」。I18 design §3.17.6 的 `Adjudicate` 门禁指的是**检测层 L4**（内核强制隔离），由本阶段的虚拟化层 L1/L2 后端关闭（I56 §6.6）。

### 2.2 封闭词汇

沙箱三词（`SandboxKind` / `SandboxEnforcement` / `SandboxDimension`）的唯一定义随 I53（已归档）固定；工具侧词汇的唯一定义在 I56：

| 词 | 定义所在 | 取值 |
|---|---|---|
| `CommandClass` | I56 §5.2 | `readOnly` / `mutating` / `network` / `destructive` / `unknown` |
| `ReadableScope` | I56 §8.7 | `workspace` / `toolOutput` |
| `readToolOutput` | I56 §8.7 | 恒 `Ask`，独立于审批级别 |

本文只使用、不定义。

### 2.3 三层职责，互不替代

| 层 | 回答的问题 | 归属 | 失败方向 |
|---|---|---|---|
| Policy | 「这个意图按规则该不该问」 | `runtime/policy.rs` | 未知 → `Ask` |
| 审批 | 「用户要不要放行这一次」 | `runtime/gateway` + 审批卡 | 无审批通道 → `Deny` |
| 沙箱 | 「放行之后最多能做到哪」 | `sandbox/`（规格见 I53，已归档） | 无边界 → 不注册工具 |

三条硬规则：

1. **沙箱不得改变审批决策**：`execute` 在 `dangerous_only` 档恒为 `Ask`（`base_rules` 现状），在 `none` 档恒为 `Allow`；沙箱不参与求值，只在执行阶段生效；
2. **审批不得依赖沙箱结论放宽**：审批键里携带隔离强度（I56 §6.2）是为了「降级后不复用授权」，不是为了「有沙箱就免审」；
3. **字符串匹配不得作为拦截依据**：`shell` 的 `validate_input` 只校验参数形状与 `cwd` 边界，不解析命令语义；命令分类器只用于展示与 P10-b 输入。

## 3 沙箱准备（已归档，指针）

沙箱后端抽象、`SandboxPlan` 推导、链式探测与注册期收口、`enforcement` 判据、三平台后端实现、固定敏感目录、依赖变更与「不做的事」的**唯一来源**是 I53 沙箱准备规格（已归档）。本节不复述，只消费其中三条结论：

1. 探测结论 `enforcement == none` → **不注册** `shell`（I53 §4.4），运行期再读缓存仍为 `none` 则拒绝执行；
2. `SandboxPlan` 的 `writable_root` / `program` / `network` **不可**由模型输入指定（I53 §4.3）；
3. `SandboxChild::kill_tree` 必须回收**整棵**进程树且可重复调用（I53 §4.2、§6）。

> 归档后果：沙箱侧的实现细节已冻结。若要改沙箱行为（新增后端、改掩码、改探测判据），**必须**另立规格，不得直接改代码后回写本文——本文与 I56 都不再承载沙箱内部口径。

## 8 阶段边界：后台任务（未立项）

后台任务（异步执行 / 任务 id / 状态机 / 轮询回收 / 跨 turn 存活）属 [roadmap §2.1](./I38-agent-roadmap.md) 的 P9 continuity 轴，需单独 ADR；§1.2 已将其列为 P14 非目标。**改动面（E1–E8）、与 P14 的接口约定与立项前置（G1–G6）的唯一来源是 [I52-Ext](./I52-ext-background-task.md)**，本节不复述。

本文只留三条约束：

1. `shell` 的执行正确性论证建立在「一次工具调用 = 一次同步执行」上（deadline 在调用栈、`kill_tree()` 与 `sink.finish()` 返回前必调、进程归属由 `TurnTasks` 代际收口）；工具内部提前返回会让这四条同时悬空，因此后台形态不在本阶段「顺手接」；
2. P14 **不得**为后台任务预留 `task_id` / `job_*` 字段、状态分支或半成品路径——预留即半实现，会让终态矩阵出现第三态；
3. 判据：P14 的不变量是「**调用结束 = 进程树已回收**」，后台任务要把它改成「**任务结束 = 进程树已回收**」；因此第一件事是换持有者，不是加参数。
