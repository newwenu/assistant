# 代码拆分原则

> 性质：**工程原则（唯一来源）**｜适用范围：`src-tauri/` 全部 Rust 代码，前端 TS 模块的拆分判据同理可参照
> 本文件只写原则（判据、边界、模式、禁止事项）；执行顺序、验证命令、待拆清单、进度与扫描快照都不属于原则，不在本文件出现。其它文档需要拆分判据时只引用本文件，不复述条款。

---

## 1 主判据：一个文件只对应一个变化原因

判断是否该拆的唯一标准是**职责边界**，不是行数：

- 若同一个文件需要因两类互不相关的需求分别修改（同步策略变更 / 加密算法变更 / UI 布局变更 / DTO 契约变更 / 循环阶段变更），即为职责混杂，应拆。
- **职责数 ≥3 且彼此无共同依赖**＝明确的职责混杂信号。
- 只对应一个变化原因的文件不动，无论多长。
- **拆分粒度由职责决定，不设行数目标**：子模块大小由职责边界决定，不按“拆到多少行”切；若某个子模块仍承担两类变化原因，继续按职责拆，而不是按行数切。

---

## 2 行数只作初筛，不作判据

行数用于决定“先看哪些文件”，不构成拆分义务，也不作为验收标准：

| 档位（非空行） | 动作 |
|---|---|
| ≥900 | 优先审查，必看职责数 |
| 300–899 | 视职责数决定 |
| <300 | 一般不动 |

统计口径：非空行，含注释与内联测试。行数在任何文档中都只是某一时点的快照，允许偏差，不承诺精确。

---

## 3 内联测试的处理：移测试，不拆实现

内联测试超标会让文件“看起来超长”，但职责并不混杂。此时动作是**把测试外移**，实现文件保持不动：

- 外移到 `<crate>/tests/<主题>.rs` 集成测试；
- 若被测项不是公开 API，用 crate 的 `internal-tests` feature 门禁（`#[cfg(all(test, feature = "internal-tests"))]`）替代 `#[cfg(test)]`；
- **不把测试当作拆分理由**。

---

## 4 目录模块模式

`foo.rs` → `foo/mod.rs` + 子模块：

1. `mod.rs` 只放：类型定义、共享常量、模块声明、组合入口、对外 `pub use`。
2. 子模块按**职责**命名（`query` / `write` / `history` / `emergency` / `validate` / `create`），不按行号或 `part1` / `part2`。
3. 共享项用 `pub(super)` 暴露；对外 API 用 `pub use sub::*` 保持不变。
4. 同一 crate 内允许多个 `impl` 块分散在不同子模块（如 `impl SecurityDbState` 分在 `entries/*.rs`），这是首选的低风险手段，不必强行收敛到单文件。
5. 同一文件内的 `impl` 方法不需要函数级 re-export；只有 free fn 跨子模块调用时才需要 `pub(super)` / `pub(crate)`。

---

## 5 职责边界判据

- **组合入口留在上层 `mod.rs`**（如 `get_conversation_detail`、`sync_now`），避免子模块互相调用形成环。
- **共享叶子下沉**：被两个以上子模块调用、且不依赖任一子模块的纯函数（事务封装、字段加解密、生命周期 `readyness` / `prepare` / `finalize`、纯预览 helper），独立成叶子模块，两侧只依赖它，耦合即消失。
- **状态集中**：`static mut` 全局单例、跨模块交换的状态变量必须集中到一个 `state.rs`，否则按函数就近定义会产生双向 `use super::` 与 `unsafe` 别名冲突。
- **平台相关代码按平台分文件**（`windows.rs` / `macos.rs` / `linux.rs`），用 `cfg` 在父模块收口；与既有 `unlock_dialog/`、`screen_lock/` 范式一致。
- **业务编排下沉**：command / cmd 层只做参数校验 + 调 domain + 发事件，提示词构建、provider 调用、流消费、落库属于 domain 或独立 pipeline 模块。
- **宏边界不可搬移**：`async_stream::stream!` 内的 `yield` 不能移出宏，策略是把状态与分支逻辑抽成返回 `Vec<_>` 的纯函数，宏内只保留 `for ... { yield }`。

---

## 6 依赖方向：单向，无环

子模块只通过 `super::` 单向引用；每个子模块在文档或注释里应能写出“依赖谁”。

出现以下形态即说明职责归属错了，需重新划分而非加 `pub`：

- `A → B` 与 `B → A` 同时存在（双向环）；
- “编排依赖应急 / 历史依赖编排”这类反语义边；
- 为打破环而把函数塞回 `mod.rs`，导致 `mod.rs` 反而变成最大文件。

---

## 7 禁止事项

- 不为拆分而拆分：职责单一的文件不动，与行数无关。
- 不改公开 API：函数签名、类型定义、`pub use` 路径全部保持。
- 不引入循环依赖。
- 不在 `async_stream::stream!` 宏外使用 `yield`。
- 不把测试当作拆分理由。
- 不做“搬移 + 改写”混合提交：纯机械搬移与语义改写分开提交，便于回滚与定位。
- 不新增本机绝对路径到 `docs/` 下任何 md；仓库内引用一律相对路径。
