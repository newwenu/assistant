> 定位：W1 交付**画布设施**（视口、坐标、渲染、失效调度）；W2 在画布上放的是**真实卡片**——按编排分析的卡片类别（执行卡片四型 + 容器卡片）各展示一张，六件构成全部在场；12 个 L1 阶段**不再各自成卡**，而是降为轮次卡片主体内的**阶段轨道**（§7.2）。画布左侧另设**放置栏**，列出这几种卡片，可拖入画布生成卡片；放置行为只改画布会话状态，**不承诺校验、不承诺自动接线、不承诺持久化**（§7.10）。
>
> 卡片内容为**示例常量**（引用 / 参数 / 交接类型均为占位），界面必须显式标注「示例数据」，不得让人误读为真实运行（§7.5 / A25）。W2 的画布是**可编辑**的：卡片可拖拽重排，连线可选中 / 断开 / 重连；编辑结果只落画布本地状态，不回写模板、不保证持久化（§6.1）。

本文中的「必须 / 禁止」为可验收约束；「应当」为默认做法，偏离需在代码注释里写明理由。

## 1 范围与边界

### 1.1 交付什么

| # | 目标 | 判据 |
|---|---|---|
| 1 | 预设实体：标识（id / 名称键 / 说明键）+ 卡片清单（按卡片类别）+ 区带命名 + 连线策略 | A1 / A2 / A12 |
| 2 | 预设摆放：区带 + 列位 → 盒子，纯函数、零测量 | A6 / A7 / A8 / A9 |
| 3 | 可编辑连线：4 条示例连线全部呈现，端点落在卡片边框锚点；可选中、可断开、可重连（编辑结果只落画布本地状态） | A5 / A10 / A11 |
| 4 | 预设标识可见：头信息行显示预设名 + 「内置」标记 + 「示例数据」提示 + 编辑提示 | A13 / A25 |
| 5 | 术语闭环：预设 / 区带 / 摆放 / 连线对齐词表；L2 词只以「示例」形态出现并显式标注（§2.4） | A14 |
| 6 | 真实卡片呈现：5 张卡片（轮次 / 工具调用 / 会话 / 人工介入 / 会话容器），六件构成（头部 / 主体 / 端口区 / 脚部 / 选择态 / 拖拽柄）全部在场 | A15 / A16 / A19 / A20 |
| 7 | 阶段轨道：12 个 L1 阶段作为轮次卡片主体内的 12 条阶段条，与模板一一对应；阶段条不是卡片 | A17 / A23 |
| 8 | 放置栏：左侧列出 5 种卡片类别，可拖入画布生成卡片；只落画布会话状态，不校验、不自动接线、不持久化、不写模板 | A24 |
| 9 | 示例数据标注：卡片内容为示例常量，头信息行与卡片头部都有「示例」标记 | A25 |

### 1.2 不交付什么

| # | 排除项 | 理由 |
|---|---|---|
| 1 | 编辑结果持久化：写模板、发命令、回写 wire | 后端 L2 未接入；W2 的编辑只落画布本地状态（§6.1） |
| 2 | 类型化端口与交接校验 | 交接类别闭集未定案；端口只画**占位类型标签**，不参与校验（§2.4 / T-21） |
| 3 | 参数编辑：参数表单 / 参数 schema / 参数校验 | 编辑模式未立项；W2 只做**参数摘要**（只读键值对，§7.3） |
| 4 | 嵌套子图 | 容器卡片未立项；只画**子图缩略**（纯装饰，不可交互，§7.3） |
| 5 | 吸附 / 对齐辅助线 / 网格对齐 | 属编辑增强，非编辑能力本身；W2 只做自由拖拽 |
| 6 | 用户预设：新建 / 导入 / 导出 / 重命名 | 需 schema + 版本 + 持久化，属 L2 范畴 |
| 7 | 多预设并置或切换 | W2 只有一份内置画布预设（OQ-2） |
| 8 | 预设绑定内置模式（模型 / 工具 / 审批） | 预设只描述**摆放**，不描述运行配置（§2.5 易混词表 / OQ-1） |
| 9 | 自动布局（dagre / 力导向）与自动 fit | 5 张卡片不需要图算法；自动 fit 需测量（W1 §1.2 第 9 条） |
| 10 | 卡片内容自适应宽度 | 内容决定几何 → 需测量，违反 N3 |
| 11 | 放置栏的真实能力：放置校验 / 自动接线 / 落库 / 刷新保留 | 放置只是**视觉演示**（§7.10 / A24） |
| 12 | 真实运行数据（输出预览 / 错误详情 / 计时器） | 需 run 台账；卡片只呈现示例常量与阶段状态（§7.5） |

### 1.3 与 W1 的关系

| 层 | W1 交付 | W2 增量 |
|---|---|---|
| 视口 | `CanvasViewport`：视口、缩放、平移 | 不改；页面改为「左放置栏 + 右视口」两栏（§7.10） |
| 几何 | `layoutTemplate(entries)`：模板 → 盒子 | 新增 `layoutPreset(preset)` 作为**唯一布局入口**，内部仍调用 `layoutTemplate`（公式只有一份） |
| 渲染 | `CanvasCard` / `CanvasEdge` / `CanvasLegend` | `CanvasEdge` 端点改由锚点推导并支持编辑；`CanvasCard` 按 §7 重做（六件构成 + 阶段轨道）；新增 `CanvasPalette`（放置栏）、`CanvasPresetBadge` |
| 内容 | 12 张卡片 + 12 条边 + 出口，来源是模板常量 | 内容来源改为**预设**（预设声明 5 张示例卡片 + 4 条示例连线；阶段清单引用模板，不复制） |
| 调度 | `subscribeProjections` 帧合并 | 不改；预设与投影正交（阶段状态是唯一投影输入） |

**单向派生链**（不得反向）：

```
turn 模板（AGENT_NODE_TEMPLATE：12 条阶段的 order / 名称键）
        │ 阶段清单被引用（不复制）
        ▼
内置画布预设（preset：5 张示例卡片 + 区带 + 列位 + 示例连线策略）
        │ layoutPreset()
        ▼
初始盒子（CanvasBox：x / y / w / h） ── 常量，模块加载时算一次
        │ 用户拖拽 / 放置栏放置（编辑层，仅改画布本地状态）
        ▼
卡片 / 连线 / 放置栏条目 / 区带标签（DOM）
```

**编辑不反向污染预设**：预设定义仍是编译期常量；用户编辑产生的是画布会话状态，不回写预设、不回写模板。

**模板的用途收窄**：模板在 W2 只提供**阶段清单**（轮次卡片主体里的 12 条阶段条），不再提供画布卡片清单与画布边集。这条收窄是本规格相对初版的最大变化（T-24）。

### 1.4 与词表的差异（有意校正，登记见 §15）

| # | 词表表述 | 本规格 | 理由 |
|---|---|---|---|
| D-1 | §2.5.2 原无「预设」；该词被旧文档用作「内置模式」的别称 | 收回「预设」为**画布预设**（命名）；旧称改判**内置模式** | 内置 Agent 抽象需要一个画布侧的名字，且必须与「模板」「内置模式」区分（§2.5 易混词表 / T-11） |
| D-2 | §2.5.3 锚点是「格子边缘的纯几何锚定位置」 | 锚点同样用于**画布卡片边缘** | 纯几何、不承载类型，定义完全同构（T-15） |
| D-3 | §2.5.2 连线 = 接线的渲染形态 | 连线可以**没有**对应接线（前端编辑态呈现） | W2 无交接类别实例，连线只是示例路径，可编辑但不落 L2（T-14 / T-20） |
| D-4 | §2.5.2 工具分支（tool lane） | 区带语义改为**主链区带 / 分支区带** | 画布上不再按 turn 模板分行：主链区带放会话→轮次→工具，分支区带放人工介入与容器（T-22） |
| D-5 | §2.5.1 执行卡片 = 引用执行单元 + 参数 + 类型化交接契约 | W2 以**示例卡片**呈现执行卡片四型与容器卡片；引用 / 参数 / 交接类型均为占位常量 | 先有形才能讨论形；未定案部分用「示例」标注，而不是回避不画（T-21 / T-26） |
| D-6 | §2.5.1 卡片主体随「模式 × 缩放」决定内容，概览态 = 运行摘要 | 主体 = **参数摘要 + 阶段轨道 / 内容占位** | 卡片是画布对象而非读数板；运行摘要下沉为脚部药丸（T-23） |
| D-7 | §2.5.1 卡片类别闭集未定案 | 画布上出现「执行卡片 · 轮次」这类徽标 | 徽标右半是**示例分型名**，且必须与「示例」标记同现；不得表述为「类别已定案」（§2.4） |

### 2.1 沿用术语（出处已在词表，本规格不复述定义）

| 层 | 术语 | 出处 |
|---|---|---|
| 画布设施 | 画布、视口、缩放、平移 | 词表 §2.5.2 |
| 内容 | 卡片、卡片模式、运行摘要、盒子 | 词表 §2.5.1 / §2.5.2 |
| 拓扑 | 模板、边、相位 | 词表 §2.5.3 |
| 渲染 | 锚点、边、连线 | 词表 §2.5.2 / §2.5.3 |
| 观测 | 圈、出口 | 词表 §2.5.3 |
| 原语 | 模板常量、边集常量、投影、折叠、调度、帧合并 | 词表 §2.6 |

### 2.2 新增术语（性质：命名）

| 术语 | 英文 | 定义 | 为什么需要 |
|---|---|---|---|
| **画布预设** | canvas preset | 画布上的一组**预置呈现方案**：卡片清单 + 区带命名 + 连线策略 + 文案标识；不含坐标、不含参数 | 内置 Agent 抽象在画布上需要一个可命名的整体；「图」「模板」都已被占用（§2.5 易混词表） |
| **内置画布预设** | built-in canvas preset | 随应用发布的画布预设（编译期常量，`builtin: true`）；与「用户预设」（未立项）相对 | 区分「代码内置」与「用户创建」 |
| **预设摆放** | preset placement | 把预设的卡片按区带与列位换算成世界坐标盒子的过程；原语 `layoutPreset` | 用户词「摆放」↔ 原语 `layoutPreset`，成对给出（词表 §2.6.7 第 4 条） |
| **区带** | zone | 世界坐标的行语义分区；一个区带承载一组卡片，并有一个说明标签 | 摆放需要「行 = 什么含义」的名字，不能只说 row 0 / row 1 |
| **主链区带** | main lane | 第一行区带：会话 → 轮次 → 工具调用，从左到右 | 与「分支区带」并列，构词对称（T-22） |
| **分支区带** | branch lane | 第二行区带：人工介入与容器，条件进入而非时间先后 | 「条件进入」是区带语义，需要独立命名（T-22，取代词表「工具分支区带」） |
| **示例卡片** | example card | 以真实卡片类别为**形**、以占位常量为**内容**的展示卡片；不产生任何运行效果 | 未定案的卡片类别需要先有可见形态；必须有一个名字把「展示」与「定案」分开（T-26） |
| **卡片类别示例表** | card kind table | 5 种示例卡片的单一来源表（类别 / 分型 / 名称键 / 说明键 / 引用 / 参数 / 端口 / 主体类型 / 色调） | 画布与放置栏必须共用一张表，否则两处漂移（A1 / A24） |
| **阶段轨道** | stage track | 轮次卡片主体内的 12 条阶段条，按模板 `order` 排列；阶段条不是卡片 | 12 个 L1 阶段需要一个「住在卡片里」的容器名（T-24） |
| **阶段条** | stage bar | 阶段轨道里的一格：序号 + 名称 + 状态点；无头部、无端口、无拖拽柄 | 与卡片同层出现时必须能一眼区分（A17） |
| **放置栏** | palette | 画布左侧列出可用卡片类别的固定栏；条目可拖入画布生成卡片 | 「从哪儿拿卡片」需要独立命名，不能塞进画布或头信息行（T-25） |
| **占位端口** | placeholder port | 圆点 + 占位类型标签（如 `turn.in`）；不做校验、不承载输入输出槽 | 卡片形态要求端口区在场，但交接类别未定案（T-21） |
| **参数摘要** | param summary | 只读的「参数名 + 示例值」列表；不可编辑、无 schema、无校验 | 卡片形态要求参数在场，但编辑模式未立项（T-23） |
| **可编辑连线** | editable connector | 连线的编辑形态：可选中、可拖拽端点重连、可断开、可删除；编辑结果只落画布本地状态 | 「可编辑」必须落在连线这一层（T-20） |
| **源锚点 / 目标锚点** | source anchor / target anchor | 连线两端落在卡片边框上的几何点（起端 / 终端） | 词表只有无方向的「锚点」（T-15） |

### 2.3 用词纪律

| 禁止 | 应写 | 说明 |
|---|---|---|
| 「节点」 | 卡片 / 阶段条 | 「节点」是原语词（`ObservationNode` / `WorkflowNode`），不是用户词（W1 §2.2） |
| 「执行体」「执行单元」用于正文 | 引用（槽名） | 「执行单元」只作为引用槽的占位值出现（`turn` / `shell` / `conversation` / `ask_user`，原语量），不作正文名词 |
| 「接线」 | 连线 / 边 | W2 无交接类别实例；「接线」只用于 L2 语义（§6.2 / T-14） |
| 「端口」用于无类型的位置点 | 编辑锚点 | 只有圆点、没有类型标签时叫编辑锚点（§6.3） |
| 「端口」用于有类型标签的位置点 | 占位端口 | 必须带「占位」二字，并说明不校验（§2.4 / T-21） |
| 「参数表单」「参数项」「参数 schema」 | 参数摘要 | W2 只读、无控件、无校验（§7.3） |
| 「卡片类别」不加「示例」 | 示例卡片类别 | 类别闭集未定案，任何场合都必须带「示例」（§2.4） |
| 「内置预设」 | 内置模式 | 旧称指运行配置 seed，与画布预设无关（词表 §2.5.4 / T-11） |
| 「预设」不加限定 | 画布预设 | 「预设」已收回给画布侧；正文的「预设」是简称，代码符号 `preset` 不变 |
| 「节点模板」「模板」不加限定 | turn 模板 / 工作流模板 / 画布预设 | 三者不同层，命名混用是最大返工来源（词表 §2.5.4） |
| 「布局」用于用户文案 | 摆放 | 用户词是「摆放」，代码原语是 `layoutPreset` / `CanvasLayout` |
| 「格子」「单元格」 | 卡片 / 盒子 | 本规格画的是画布，不是观测栅格（W1 §1.5 T-10） |
| 「容器」用于区分层级 | 画布 / 观测栅格 / 容器卡片 | 「容器」是描述词不是术语（词表 §2.5.4）；DOM 承载盒可称容器，但不作层级名 |
| 「自动保存」「已保存」「已同步」「已生效」 | （不出现） | 编辑与放置都不持久化，不得暗示已落库或已生效（§8.4） |

### 2.4 L2 词的出现方式（以「示例」形态出现，不是禁用）

W2 的卡片是**示例卡片**：形按词表定义做全，内容用占位常量填。下表是每个 L2 词的允许出现方式与标注要求：

| 词 | 词表定义 | W2 出现方式 | 标注要求 |
|---|---|---|---|
| 执行卡片 execution card | 引用一个执行单元的卡片 | 以示例卡片出现，四型：轮次 / 工具调用 / 会话 / 人工介入（§7.1） | 头部徽标写「执行卡片 · {分型}」，并与「示例」标记同现 |
| 容器卡片 container card | 承载子图的卡片（先占名、未立项） | 以示例卡片出现，主体画**子图缩略**（纯装饰） | 头部徽标写「容器卡片」，边框虚线，带「示例」标记 |
| 执行单元 execution unit | 被卡片引用的实体 | 只作为**引用槽**的占位值（原语量，如 `turn` / `shell`） | 引用槽不翻译、不加「真实」措辞 |
| 卡片类别 card kind | 执行卡片按执行单元分型，闭集未定案 | 徽标右半的分型名（轮次 / 工具调用 / 会话 / 人工介入） | 必须与「示例」标记同现；不得写「类别已定案」 |
| 端口 / 交接类别 | 视觉锚点 + 命中区 + 类型声明 | **占位端口**：圆点 + 占位类型标签 | 类型标签是占位字符串（原语量，如 `turn.in`），不做校验（T-21） |
| 参数 / 参数 schema | 用户填的常量配置及其定义 | **参数摘要**：3 行「参数名 + 示例值」 | 只读；不得出现输入控件、必填标记、校验文案 |
| 接线 / 连接句柄 | 类型化交接实例及其端点 | 不出现 | 连线可编辑但不叫接线 |
| 调度语义（就绪集合 / 激活 / 冲突域） | 编排调度语义 | 不出现 | 画布编辑不改变运行调度 |

**一句话**：W2 用「形全、内容占位、标注示例」的方式展示卡片，既不把未立项的能力说成已交付，也不因为未定案就不画。

### 2.5 易混词：画布预设 / 模板 / 模式

| 概念 | 是什么 | 数据位置 | 谁可改 | W2 是否出现 |
|---|---|---|---|---|
| **画布预设** | 画布呈现方案（5 张示例卡片 + 区带 + 列位 + 示例连线 + 文案） | 前端编译期常量（编辑结果另存画布会话状态） | 代码（内置定义）+ 用户（画布内编辑 / 放置，不持久化） | 是（唯一一份） |
| **turn 模板** | L1 观测拓扑：12 条模板条目的 `order` / 名称键 | 前端编译期常量 | 代码 | 是（**只提供阶段清单**，供阶段轨道） |
| **工作流模板** | L2 可编辑图：`WorkflowNode` + 参数 + 类型化交接 | 后端存储 | 用户 | 否（未立项；卡片只是示例形） |
| **内置模式** | 运行配置：模型 / 工具 / 审批等级（旧称「内置预设」） | 后端存储 | 用户 | 否（与摆放无关） |

一句话：**画布预设回答「画布上摆哪些示例卡片、怎么摆」，模板回答「轮次内部有哪些阶段」，内置模式回答「跑起来用什么」**。三者不可互换，也不可拼词。

## 4 预设模型

### 4.1 预设是什么 / 不是什么

| 判定 | 结论 | 依据 |
|---|---|---|
| 是画布内容的呈现方案吗 | 是（5 张示例卡片的清单与摆放） | 本规格 §4.2 |
| 可在画布内编辑吗 | 是（仅画布层）：卡片可拖拽、可从放置栏添加、连线可断开 / 重连 | 编辑结果存画布会话状态 |
| 是工作流图吗 | 不是 | 无 `WorkflowNode`、无参数 schema、无交接类别 |
| 是模板吗 | 不是 | 预设引用模板的**阶段清单**，不复制；模板是轮次拓扑，预设是画布呈现 |
| 是运行配置吗 | 不是 | 不含模型 / 工具 / 审批 |
| 存坐标吗 | 不存 | 初始坐标是派生量（§4.4）；编辑坐标只存画布会话状态 |
| 可序列化吗 | 可（纯数据常量），但 W2 不做导入导出 | OQ-3 |

### 4.2 三件构成

| 件 | 内容 | 不变量 |
|---|---|---|
| **标识** | `id`、`titleKey`、`descriptionKey`、`builtin: true` | 文案只走 i18n；`builtin` 是字面量类型 |
| **内容** | 卡片清单（按卡片类别，每类一张）+ 区带表（行号 + 说明键 + 留白列）+ 阶段轨道来源（turn 模板） | 不复制模板的 `row` / `column` / 边集；类别内容由 `CARD_KINDS` 提供 |
| **策略** | 连线可编辑（`source: "preset-example"`：4 条示例连线由预设显式声明；`editable: true`） | 连线集合不来自模板边集；编辑后以画布状态为准 |

### 4.3 类型定义（`src/features/canvas/presets/types.ts`）

```ts
import type { I18nPath } from "@/i18n";
import type { CardTone, ExitTone } from "../types";

export type CanvasPresetId = "builtin-agent-turn";

export type CanvasZoneId = "main-lane" | "branch-lane";

/** 示例卡片类别（展示用闭集，不是 L2 定案；见 §2.4）。 */
export type CardKindId =
  | "execution-turn"
  | "execution-tool"
  | "execution-conversation"
  | "execution-hitl"
  | "container-conversation";

/** 参数摘要的一行：参数名走 i18n，示例值是原语量。 */
export interface CardParamSpec {
  labelKey: I18nPath;
  value: string;
}

/** 占位端口：类型标签是原语量（如 `turn.in`），不做校验。 */
export interface CardPortSpec {
  side: "left" | "right";
  typeLabel: string;
}

/** 主体附加区：轮次卡片放阶段轨道，其余放内容占位。 */
export type CardBodyKind = "stages" | "output" | "messages" | "question" | "subgraph";

/**
 * 卡片类别规格：画布与放置栏共用这一张表（单一来源，A1 / A24）。
 * 全部字段是示例常量，不来自运行、不来自后端。
 */
export interface CardKindSpec {
  id: CardKindId;
  category: "execution" | "container";
  /** 分型短名（徽标右半）；容器卡片为 `null`。 */
  formKey: I18nPath | null;
  nameKey: I18nPath;
  /** 放置栏里的一句话说明。 */
  summaryKey: I18nPath;
  /** 引用槽占位值（原语量，如 `turn` / `shell`）。 */

  ports: readonly CardPortSpec[];
  body: CardBodyKind;
  /** 示例色调（示例数据，不来自运行）。 */
  tone: CardTone;
  /** 示例出口：只有轮次卡片有。 */
  exit?: ExitTone;
}

export const CARD_KINDS = {
  /* …5 类，见 §7.1 表… */
} as const satisfies Record<CardKindId, CardKindSpec>;

/** 区带：世界坐标的行语义分区。 */
export interface CanvasZone {
  id: CanvasZoneId;
  /** 世界坐标行号（由预设声明，不由顺序推断）。 */
  row: number;

  kind: CardKindId;
  zone: CanvasZoneId;
  /** 区带内列位（示例摆放的固定列，由预设显式声明；不查模板）。 */
  column: number;
}

/** 示例连线：按类别声明端点（每类恰好一张卡，故类别即端点）。 */

  to: CardKindId;
  route: "horizontal" | "vertical";
}

/** 连线策略：示例连线由预设声明，不从模板边集派生；连线本身可编辑。 */

  source: "preset-example";
  /** 可编辑：可选中、可拖拽端点重连、可断开、可删除；不保证持久化。 */
  editable: true;
}

  id: CanvasPresetId;
  builtin: true;
  titleKey: I18nPath;
  descriptionKey: I18nPath;

  /** 阶段轨道来源：12 条阶段条来自 turn 模板（不复制）。 */
  stages: { source: "template-nodes" };
}

/** 布局入口：预设 + 卡片度量 → 盒子（无 DOM、无视口）。 */
export function layoutPreset(preset: CanvasPreset): CanvasLayout;
```

`layoutPreset` 的实现必须是「预设 → 布局条目 → W1 的 `layoutTemplate`」两步，**不得**另写一套坐标公式：

```ts
export function layoutPreset(preset: CanvasPreset): CanvasLayout {
  const rowByZone = new Map(preset.zones.map((zone) => [zone.id, zone.row]));
  const entries = preset.cards.map((card) => ({
    id: card.kind,
    row: rowByZone.get(card.zone) ?? 0,
    column: card.column,
  }));
  return layoutTemplate(entries, CARD_METRICS);
}
```

`layoutTemplate(entries, metrics)` 是 W1 §5.5 的几何函数（公式不变，度量由第二参注入），W2 不改它的公式。

**卡片度量与格子度量分离**（`src/features/canvas/presets/metrics.ts`）：

```ts
/** 画布卡片度量：与观测栅格的 CANVAS_METRICS 无关，不得互相引用。 */
export const CARD_METRICS = {
  cellW: 320, cellH: 240, gap: 32, loopGutter: 0,
} as const satisfies CanvasMetrics;
```

字段名沿用 W1 `CanvasMetrics` 的 `cellW` / `cellH`（设施只认「单元宽高」这一抽象），但**取值与用途独立**：320×240 是 §7.4 分区预算的结果，不是把观测栅格的 132×78 放大。`loopGutter = 0`：画布上没有回边，不再需要顶部外轨（T-26）。`layoutTemplate` 的默认度量仍是 `CANVAS_METRICS`（W1 行为不变），只有预设显式传入 `CARD_METRICS`。

### 4.4 预设不存坐标（编辑结果也不进预设）

| 理由 | 后果（若存坐标） |
|---|---|
| 初始坐标是 `CARD_METRICS` + 预设列位的派生量 | 改 `cellW` / `gap` 后旧坐标错位，出现两套几何 |
| 用户拖拽与放置结果只属画布会话 | 写进预设会让「预设定义」与「本次视图」混为一谈，刷新后无法回到初始摆放 |
| 预设要可校验（A3 / A8 / A9） | 坐标无法与预设做一致性断言 |
| 持久化归 L2 工作流模板 | 前端把编辑坐标写进预设，会让「谁是真值」变成两处 |

**列位不是坐标**：`PresetCard.column` 是摆放语义（「这张卡在第几列」），可校验、可读，不随度量变化；`x` / `y` 才是坐标，禁止出现（A12）。

### 4.5 不可变性与编译期锁

- 预设定义常量必须 `Object.freeze`（深冻结到 `zones` / `cards` / `connectors` 数组），运行时不可改写；用户编辑只写画布会话状态。
- `CARD_KINDS` 用 `satisfies Record<CardKindId, CardKindSpec>`：新增类别未补表即**编译失败**（A1）。
- `cards` 用 `satisfies readonly PresetCard[]`，且每个 `CardKindId` **恰好出现一次**（A2）；阶段轨道条目数与模板一致（A23）。
- 预设不得含函数、不得含坐标、不得含 i18n 译文（只有键）。

## 5 摆放模型（核心）

### 5.1 三层分离

| 层 | 产物 | 谁产生 | 可否读 DOM |
|---|---|---|---|
| 拓扑层 | 阶段清单：模板 `order` / 名称键（只供阶段轨道） | 编译期常量 | 否 |
| 摆放层 | 初始盒子：`x` / `y` / `w` / `h` + 区带归属 | `layoutPreset()` 纯函数 | 否 |
| 编辑层 | 编辑后的盒子 / 新增卡片 / 连线端点 | 画布会话状态（用户拖拽 / 放置栏） | 否（位移由指针事件给出） |
| 渲染层 | 卡片 / 连线 / 放置栏 / 区带标签的 DOM | `CanvasCard` / `CanvasEdge` / `CanvasPalette` | 否（几何来自摆放层或编辑层） |

**分层纪律**：区带归属只属于摆放层；卡片组件不得自己判断「我在第几行」，否则同一语义出现两处实现。编辑层只叠加位移与端点改写，不重算区带归属。

### 5.2 区带

世界坐标（卡片度量 `cardW = 320`、`cardH = 240`、`gap = 32`、`loopGutter = 0`，来自 §4.3 `CARD_METRICS`；公式仍归 W1 §5.5）：

| 区带 | 行 | 世界 `y` 范围 | 卡片 | 说明 |
|---|---|---|---|---|
| **主链区带** main lane | `row 0` | `[32, 272)` | 会话卡片（列 0）/ 轮次卡片（列 1）/ 工具调用卡片（列 2） | 示例主链：会话 → 轮次 → 工具 |
| **分支区带** branch lane | `row 1` | `[304, 544)` | 人工介入卡片（列 2）/ 会话容器卡片（列 3） | 条件进入，不代表时间先后 |
| **出口角标** exit corner | — | 轮次卡片内右下角 | 无（汇点） | 出口不是卡片、不占轨道 |

区带与卡片归属：

| 区带 | 卡片（类别） | 列位 |
|---|---|---|
| 主链区带 | 会话卡片 / 轮次卡片 / 工具调用卡片 | 0 / 1 / 2 |
| 分支区带 | 人工介入卡片 / 会话容器卡片 | 2 / 3 |

**分支区带的留白**：列 0–1 无卡片，留给区带说明标签（`canvas.preset.zone.branch_lane`）。留白是**几何事实**（`labelColumns = [0,1]`），不是「空卡片」。列 2 对齐是为了让「工具调用 → 人工介入」走**同列跨行**的竖线（§6.5），不用斜线。

### 5.3 摆放规则

| # | 规则 | 判定方式 |
|---|---|---|
| P1 | 一区带一行：区带之间不折行、不混排；卡片行号恒等于所属区带的 `row` | A3 / A4 |
| P2 | 列位由预设声明：卡片 `x` 只由 `PresetCard.column` 决定，同一列跨行对齐（工具调用与人工介入同为 `column 2`） | A9 |
| P3 | 等距：列间距 = 行间距 = `gap`；卡片宽高恒定为 `cardW` / `cardH`，不随文案长度变化 | A8 |
| P4 | 顶部留白 = `gap`：`loopGutter = 0`（画布无回边），第一行 `y` 起点 = `gap` | A9 |
| P5 | 左起原点：`x` 原点 = 0，最左卡片贴世界左边界；不做水平居中 | A9 |
| P6 | 留白不画：区带 `labelColumns` 范围内不出现卡片，只出现区带标签 | A4 |
| P7 | 出口内嵌：出口落在轮次卡片内部，不占轨道、不改几何 | A9 |
| P8 | 零测量：初始摆放只吃预设 + `CARD_METRICS`；同一预设在任何视口尺寸下产出同一初始坐标（用户拖拽 / 放置另走编辑层，不经过摆放函数） | A6 / A7 |

### 5.4 坐标公式

**唯一公式在 W1 §5.5，本规格只做输入替换**：

| 项 | 公式 |
|---|---|
| `x` | `column * (cardW + gap)` |
| `y` | `loopGutter + gap + row * (cardH + gap)` = `32 + row * 272` |
| `w` / `h` | `cardW` / `cardH` = `320` / `240` |
| 世界宽 | `(maxColumn + 1) * cardW + maxColumn * gap` = `4 * 320 + 3 * 32` = `1376` |
| 世界高 | `loopGutter + gap + (maxRow + 1) * cardH + maxRow * gap` = `0 + 32 + 2 * 240 + 32` = `544` |

`layoutPreset` 的输出必须与「把同一条目表交给 `layoutTemplate(entries, CARD_METRICS)`」的结果**深相等**（A9）——预设只换区带命名与卡片清单，不改几何公式。

### 5.5 摆放不变量

| # | 不变量 | 断言方式 |
|---|---|---|
| N1 | 盒子两两不相交（矩形不重叠） | A8 |
| N2 | 连线端点落在盒子边框（不越入盒内） | A10 |
| N3 | 摆放函数签名不含 DOM / 视口参数 | A6 |
| N4 | 世界尺寸 = 盒子包围盒 + 顶部 `gap` | A9 |
| N5 | 每张卡片恰好属于一个区带；区带由预设声明，不由顺序推断 | A4 |
| N6 | 出口不参与几何：有无出口，盒子坐标不变 | A9 |
| N7 | 预设不含坐标字段（类型层面无 `x` / `y` / `w` / `h`） | A12 |

### 5.6 为什么这样摆（读图约定）

| 摆放选择 | 表达的语义 | 替代方案为何不行 |
|---|---|---|
| 横向 = 主链顺序（会话 → 轮次 → 工具） | 阅读方向 = 执行方向 | 纵向排会让 4 列变 4 行，视口高度失控 |
| 纵向 = 分支（人工介入与容器换行） | 「条件进入」而非「时间先后」 | 混在同一行会让人工介入看起来必然发生 |
| 工具调用与人工介入同列 | 竖线表达「工具执行中需要人介入」 | 错列只能用斜线，读图代价高 |
| 出口内嵌轮次卡片右下角 | 出口是 turn 结束的汇点，挂在轮次卡片上 | 出口独立成卡片会污染边集与焦点序列（W1 §1.3 D-3） |
| 分支区带左侧留白 + 区带标签 | 留白有语义（「仅当需要时才进入」） | 空白无标签会被读成「漏了两张卡片」 |

## 6 连线编辑

### 6.1 为什么可以编辑（前端编辑态，不依赖后端）

| # | 缺什么 | 对编辑的影响 |
|---|---|---|
| 1 | `WorkflowNode` 数据模型 | 编辑没有落库实体，结果只能存在画布会话 |
| 2 | 交接类别闭集（未定案） | 新建连线无法做类型校验，编辑结果不保证合法 |
| 3 | 模板命令通道（新建 / 改边 / 删边 + 契约） | 前端改了也发不出去，刷新即回初始摆放 |
| 4 | 模板版本 / 冻结快照 | 编辑无法追溯、无法回滚 |

**结论**：W2 先交付**前端编辑态**——连线可选中、可拖拽端点重连、可断开、可删除。编辑结果只改画布本地状态，不回写模板、不保证持久化，也不承诺「真正生效」；后端接入后（§6.6）再补持久化与校验。

### 6.2 连线 / 接线 / 边三层区分

| 层 | 是什么 | W2 是否有 |
|---|---|---|
| 语义 | 接线（wiring）：两个交接端点之间的类型化交接实例 | 无（交接类别未定案） |
| 数据 | 边（edge）：`from` / `to` / `route`（`CanvasEdgeView`，无句柄、无标签） | 有（4 条示例连线由预设声明，可编辑） |
| 渲染 | 连线（connector）：路径 + 状态 + 编辑命中区 | 有（4 条，可编辑） |

**一句话**：W2 有**边**、**连线**与**前端编辑态**，没有**接线**。所以本规格一律写「连线」，禁止写「接线」（T-14）。

### 6.3 端点 = 锚点；圆点 + 类型标签 = 占位端口

| 概念 | 构成 | W2 |
|---|---|---|
| 端口 port | 视觉锚点 + 命中区 + **类型声明** | 类型声明未定案；以**占位类型标签**呈现，叫占位端口，不参与校验（T-21） |
| 锚点 anchor | 纯几何位置，不承载类型 | 使用（源锚点 / 目标锚点） |
| 编辑锚点 edit anchor | 锚点 + 编辑命中区（仅拖拽时生效） | 使用；只有圆点、无类型标签时用此名 |
| 占位端口 placeholder port | 锚点 + 命中区 + 占位类型标签 | 使用；视觉呈现用此名 |

锚点推导（原语 `anchorOf(box, side)`，词表 §2.6.5 已规划，W2 落地为画布版本）：

| 锚点 | 位置 |
|---|---|
| 源锚点（右侧） | `x = box.x + box.w`，`y = box.y + box.h / 2` |
| 目标锚点（左侧） | `x = box.x`，`y = box.y + box.h / 2` |
| 源锚点（下侧，跨行） | `x = box.x + box.w / 2`，`y = box.y + box.h` |
| 目标锚点（上侧，跨行） | `x = box.x + box.w / 2`，`y = box.y` |

纪律：锚点只由盒子推出，**不读 DOM**；占位端口在卡片边框上以**圆点 + 类型标签**呈现（左入 / 右出；跨行时下出 / 上入），圆点是拖拽重连的命中区，类型标签是占位字符串（不翻译、不校验、不做颜色编码）。**类型标签必须与「示例」语境同现**：卡片头部有「示例」标记时，读者才知道标签不是真类型。

### 6.4 编辑约束

| # | 约束 | 实现 |
|---|---|---|
| E1 | 可命中 | 连线层 `pointer-events: auto`，命中区沿路径加宽（细线可点） |
| E2 | 可选中 | 连线可进焦点序列（`tabindex` / `aria-pressed`），选中后 `Delete` 删除 |
| E3 | 有 hover / focus 样式 | 选中与悬停只改描边 / 线宽，不改相位语义 |
| E4 | 有光标变化 | 可拖拽端点用 `grab` / `grabbing`；可选中用 `pointer` |
| E5 | 端点手柄 | 选中时显示端点手柄，拖拽到目标锚点完成重连 |
| E6 | 可删除 / 可断开 | 支持删除整条连线；断开即移除该连线，可再从源锚点重新连出 |

**相位不是编辑**：连线的四相（`untaken` / `idle` / `passed` / `active`）由投影推出，属于观测，不属于编辑；W2 的示例连线全部取 `idle`（无运行事实），编辑不改变相位来源。

### 6.5 连线几何

几何沿用 W1 §6.4 的路由约定，W2 改为「4 条示例连线」：3 条同行（水平）+ 1 条跨行（垂直），共 4 条路径 + 4 个箭头 = 8 个元素。

| # | 连线 | 路由 | 端点 |
|---|---|---|---|
| 1 | 会话卡片 → 轮次卡片 | `horizontal` | 会话右锚点 → 轮次左锚点 |
| 2 | 轮次卡片 → 工具调用卡片 | `horizontal` | 轮次右锚点 → 工具左锚点 |
| 3 | 工具调用卡片 → 人工介入卡片 | `vertical` | 工具下锚点 → 人工介入上锚点（同列 2） |
| 4 | 人工介入卡片 → 会话容器卡片 | `horizontal` | 人工介入右锚点 → 容器左锚点 |

| 改动 | 从 | 到 |
|---|---|---|
| 端点来源 | 盒子边缘偏移量（`from.x + from.w`） | `anchorOf(box, side)` 显式锚点（A10） |
| 交互声明 | 无命中区（W1 未画手势） | 编辑命中区 + 可选中 + 端点手柄（A11） |
| 集合来源 | `TEMPLATE_EDGES`（12 条） | 预设声明的 4 条示例连线（A5） |

## 7 卡片呈现（W2 交付）

### 7.1 画布上是 5 张示例卡片

| 类别 `CardKindId` | 头部徽标 | 引用槽（占位） | 参数摘要（3 行，示例值） | 占位端口 | 主体附加区 | 示例色调 / 出口 |
|---|---|---|---|---|---|---|
| `execution-turn` 轮次卡片 | 执行卡片 · 轮次 | `turn` | 模型 `default` / 预算 `64k` / 工具集 `3` | 左 `turn.in` / 右 `turn.out` | **阶段轨道**（12 条，§7.2） | `active` / `stopped` |
| `execution-tool` 工具调用卡片 | 执行卡片 · 工具调用 | `shell` | 命令 `rg …` / 超时 `30s` / 沙箱 `workspace` | 左 `tool.in` / 右 `tool.out` | 输出预览占位 | `success` / 无 |
| `execution-conversation` 会话卡片 | 执行卡片 · 会话 | `conversation` | 会话键 `conv-1` / 保留 `50` / 消息数 `12` | 左 `message` / 右 `message` | 消息流占位 | `default` / 无 |
| `execution-hitl` 人工介入卡片 | 执行卡片 · 人工介入 | `ask_user` | 问题 `ask_user` / 选项 `2` / 等待上限 `5m` | 左 `question` / 右 `answer` | 问题文本占位 | `warning` / 无 |
| `container-conversation` 会话容器卡片 | 容器卡片 | `subgraph` | 子图节点 `6` / 迭代上限 `8` / 层级 `conversation` | 左 `subgraph.in` / 右 `subgraph.out` | 子图缩略（§7.3） | `muted` / 无 |

两条纪律：

1. **形全、内容占位**：五张卡片的引用、参数、端口类型、主体内容全部是示例常量（`CARD_KINDS`），不接后端、不接运行。**示例值不得是中文句子**，只能是原语量（`default` / `64k` / `30s` 等），需要一句话说明的文案（占位标签、状态）走 i18n。
2. **示例必须标注**：每张卡片头部有「示例」徽标（`canvas.card.badge_example`），头信息行另有「示例数据」提示（`canvas.preset.badge_example`）；两者缺一即不满足 A25。

**徽标的读法**：「执行卡片 · 轮次」= 类别（执行卡片）+ 分型（轮次）。分型是**示例分型名**，不是已定案的类别闭集；容器卡片的徽标只有「容器卡片」，因为它不分型。

### 7.2 阶段轨道：12 个阶段住在轮次卡片里

12 个 L1 阶段**不再是画布节点**，也不再各自成卡。它们是轮次卡片主体里的 12 条**阶段条**：

| 项 | 结论 |
|---|---|
| 位置 | 轮次卡片主体附加区（参数摘要之下） |
| 布局 | 3 列 × 4 行，阅读顺序 左→右、上→下 |
| 每格内容 | 序号（①②…⑫，来自模板 `order`）+ 名称（`observation.node.{id}`）+ 状态点（随状态取色） |
| 每格尺寸 | 宽 `(296 - 2 * 6) / 3 ≈ 95`，高 `24`（行距 `2`） |
| 轨道头 | 一行 14px：左「阶段轨道」（`canvas.card.stages`），右阶段计数 `12`（原语量） |
| 职责文案 | 不进布局，进 `title` / `aria-description`（`observation.role.{id}`，12 键，§8.3） |
| 状态来源 | 观测投影（`observation.state.{state}`）；无投影时全部「未开始」 |
| 交互 | 阶段条**不可聚焦、不可点击、不可拖拽**；它们不是画布对象 |
| 语义 | 阶段条没有头部、没有端口、没有拖拽柄、没有选择态——**与卡片的边界就是这四件** |

**一句话**：阶段 ≠ 卡片，阶段住在卡片里。把 12 个阶段铺成 12 张卡，等于把一张卡片的内部结构误当成画布层级（R4 / T-24）。

### 7.3 六件构成（真实卡片的形，全部在场）

词表 §2.5.1 的六件构成在 W2 的卡片上全部落地：

| 构件 | 位置 | 内容 | W2 处理 |
|---|---|---|---|
| **头部** identity band | 顶部整宽 32px | 拖拽柄 + 类别徽标（`canvas.card.category.*` + `canvas.card.form.*`）+ 名称（`canvas.card.name.*`）；右端「示例」徽标 | 渲染（整宽底色 + 1px 底分隔线） |
| **主体** body | 中部整宽 182px | 参数摘要（3 行只读）+ 附加区（阶段轨道 / 输出预览占位 / 消息流占位 / 问题文本占位 / 子图缩略） | 渲染（无底色，两条子区之间 1px 分隔） |
| **端口区** port area | 卡片边框（左入 / 右出；跨行下出 / 上入） | **占位端口**：圆点 + 占位类型标签 | 渲染（圆点骑边框、凸出 5px；标签绝对定位在卡外、8px 字、不占内部预算） |
| **脚部** meta band | 底部整宽 26px | 状态药丸 + 引用 chip（`canvas.card.reference` + 原语量）+ 时长占位（左起） | 渲染（整宽底色 + 1px 顶分隔线） |
| **选择态** selection | 整卡 | 选中描边 + 可聚焦 | 渲染（§7.8） |
| **拖拽柄** drag handle | 头部左端 | 2×3 点阵（12×14） | 渲染（整卡仍是拖拽面，grip 只是可见提示，§7.8） |
| 出口角标（仅轮次卡片） | 卡内右下角，绝对定位 | `canvas.exit.*`（W1 §5.4 三态） | 渲染（不占内部预算、不改几何） |

**子图缩略**（仅容器卡片）：附加区内画 3×2 个 10×10 迷你方块 + 4 条 1px 静态连线，纯装饰、不可交互、不参与布局。它表达「这里承载子图」，不表达「子图可进入」。

**参数摘要 ≠ 参数表单**：三行「参数名 + 示例值」是只读文本，没有输入控件、没有必填标记、没有校验；需要编辑时是 L2 的事（§6.6）。

### 7.4 尺寸与分区预算（`CARD_METRICS` 是唯一尺寸来源）

| 区 | 高度 | 内边距 | 内容 |
|---|---|---|---|
| 头部 | 32px（含 1px 底分隔线） | `0 12px 0 28px`（左留拖拽柄位、右留「示例」徽标位） | 类别徽标 18px 高；名称 13px / 500，单行省略 |
| 主体 · 参数摘要 | 66px | `6px 12px` | 3 行 × 18px：参数名 11px / 示例值 11px 等宽，右对齐省略 |
| 主体 · 分隔线 | 1px | — | `--ant-color-split` |
| 主体 · 附加区 | 115px | `6px 12px` | 阶段轨道（轨道头 14 + 4 行 × 24 + 3 × 2）或内容占位 / 子图缩略 |
| 脚部 | 26px | `0 12px` | 药丸 18px 高；引用 chip 16px 高；时长 11px |
| 端口区 | 10px 圆点，垂直居中 | 骑边框、凸出 5px；类型标签在卡外 | 不占内部宽高 |
| 拖拽柄 | 12×14 点阵 | `top: 8px; left: 9px` | 落在头部左端，不占内部宽高 |
| 出口角标 | 16×16 | `right: 10px; bottom: 6px` | 仅轮次卡片，不占内部宽高 |

算式：`32 + (66 + 1 + 115) + 26 = 32 + 182 + 26 = 240 = CARD_METRICS.cellH`；横向 `28 + 268 + 12 = 308 ≤ 320 = CARD_METRICS.cellW`（左侧 28 含拖拽柄位，余 12 为右内边距与徽标位）。

端口区、拖拽柄、出口角标、端口类型标签都是**绝对定位的覆盖层**，不参与内部预算，也不改盒子宽高；分区只吃盒子内部空间，不反向影响几何，也不读 DOM；改 `CARD_METRICS` 的取值只需同步校验 §7.4 的算式（A19）。

### 7.5 内容分层：哪些是真的、哪些是示例

| 内容 | 来源 | 真 / 示例 | 说明 |
|---|---|---|---|
| 卡片类别 / 名称 / 分型 / 说明 | `CARD_KINDS` + i18n | 示例（形按词表） | 徽标与「示例」标记同现 |
| 引用槽（`turn` / `shell` / …） | `CARD_KINDS.reference` | 示例（原语量） | 不翻译、不加「真实」措辞 |
| 参数摘要（3 行） | `CARD_KINDS.params` | 示例（原语量） | 只读；不得出现输入控件 |
| 占位端口类型标签 | `CARD_KINDS.ports` | 示例（原语量） | 不校验、不做颜色编码 |
| 阶段名称 / 序号 | turn 模板 `order` + `observation.node.*` | 真（结构真值） | 与模板一一对应（A23） |
| 阶段状态 | 观测投影 | 真（有投影时）；无投影 = 未开始 | 唯一来自运行的内容 |
| 阶段职责 | `observation.role.*` | 真（文案真值） | 只进 `title` / `aria-description` |
| 出口角标 | `CARD_KINDS.exit` | 示例（示例出口） | 仅轮次卡片；`canvas.exit.*` 三态文案 |
| 连线相位 | 预设示例 | 示例（全部 `idle`） | 不接运行；编辑不改相位来源 |
| 时长 / 计数等原语量 | `CARD_KINDS` / 模板 | 示例 | 原语量，不翻译 |

**为什么允许示例内容上画布**：卡片类别闭集未定案，若等定案再画，画布上将什么都没有；先按词表的「形」把五类卡片画全、内容用占位并显式标注，才能讨论形对不对（T-26）。代价是必须做标注，且不得在任何界面文案里暗示「已接入」。

### 7.7 色调与状态

| 来源 | 取色 | 说明 |
|---|---|---|
| 卡片示例色调 | `CARD_KINDS.tone` | 示例数据；不代表运行结果 |
| 阶段状态点 | `observation.state.*` 对应的 tone | 真实投影；无投影 = `pending` |
| 连线相位 | 全部 `idle` | 示例；不接运行 |

**颜色纪律**：只取 antd CSS 变量（`--ant-color-primary` / `--ant-color-success` / `--ant-color-warning` / `--ant-color-error` / `--ant-color-text-secondary` / `--ant-color-split` / `--ant-color-bg-container`），禁止硬编码色值、禁止 `var(--x, #hex)` fallback（DESIGN §5.3）。状态不得**只**靠颜色编码：状态点旁必须有状态文案（脚部药丸或阶段条 `title`）。

### 7.8 交互与选择态

| 交互 | 触发 | 结果 | 约束 |
|---|---|---|---|
| 拖拽移动 | 在卡片任意处按下并移动（超过 3px 阈值） | 卡片盒子位移；连线端点随锚点重算 | 位移只改画布会话状态（§6.1）；不写预设 |
| 单击选中 | 点击 / `Enter` / `Space` | 进入选择态：描边加粗、可见焦点环 | 单选；选中另一张卡自动取消前一张 |
| 取消选中 | `Esc` / 点空白 | 退出选择态 | 不得改变盒子 |
| 选中后删除 | `Delete` / `Backspace` | 移除该卡片及其连线（会话状态） | 删除后不自动重排（§1.2 第 5 条无吸附 / 重排） |
| 端口拖拽重连 | 从占位端口圆点拖出 | 生成临时连线，落在目标端口完成 | 不校验类型（T-21） |

**拖拽与点击的区分**：位移超过 3px 视为拖拽，未超过视为点击（选中）；拖拽结束后不触发选中，避免「拖一下就选中」。

**选择态的视觉**：`outline: 2px solid var(--ant-color-primary)` + `outline-offset: 2px`；不得用缩放 / 阴影代替描边（避免与视口缩放混淆）。

### 7.9 键盘与焦点

| # | 要求 | 实现 |
|---|---|---|
| K1 | 卡片可聚焦 | `tabindex="0"` + `role="button"`（拖拽对象） |
| K2 | 焦点可见 | `:focus-visible` 外环，与选择态描边区分（焦点环 3px 虚线，选择态实线） |
| K3 | 焦点序列稳定 | 顺序 = 主链区带（列 0→2）→ 分支区带（列 2→3），由盒子坐标推导，不依赖数组顺序 |
| K4 | 阶段条不可聚焦 | 阶段条 `aria-hidden` 的视觉元素，不占 `tab` 序列；卡片 `aria-label` 概括「12 个阶段」 |
| K5 | 连线可聚焦 | 选中连线进序列，`Delete` 删除；连线与卡片共用一个序列，按坐标排序 |

### 7.10 放置栏（palette）

放置栏是画布左侧的固定栏，列出 5 种示例卡片类别，可拖入画布生成卡片。**它的定位是「能拿起来、能放下」，不承诺任何后端能力。**

| 项 | 规格 |
|---|---|
| 位置 | 画布页左栏，固定宽 220px，不随视口缩放 / 平移 |
| 结构 | 标题（`canvas.palette.title`）+ 说明（`canvas.palette.hint`）+ 5 个条目 |
| 条目内容 | 卡片类别徽标 + 名称（`canvas.card.name.*`）+ 一句话说明（`canvas.card.summary.*`）+ 拖拽柄 |
| 条目顺序 | 与 `CARD_KINDS` 声明顺序一致（执行卡片四型 → 容器卡片） |
| 拖入行为 | 拖到画布任意位置 → 在该位置生成一张同类示例卡片（`CanvasCardView`，id 由会话自增） |
| 生成内容 | 与该类别在画布上的卡片**完全同形同内容**（同一 `CARD_KINDS` 表，A24） |
| 生成后 | 可拖拽、可选中、可删除；**不自动接线**、不做区带归属、不做校验 |
| 刷新后 | 消失（只存画布会话状态） |
| 空态 | 不适用（放置栏恒有 5 项） |
| 无障碍 | 条目可聚焦，支持键盘选中后用方向键放置（`Enter` 在视口中心落卡） |

**为什么「功能是否可用不管」也要写清楚边界**：放置栏的价值是让人看到「这些卡片可以被拿起来放进画布」这一交互形；它一旦被读成「已支持新建卡片并保存」，就会变成错误承诺。所以规格必须显式列明「不自动接线 / 不校验 / 不持久化 / 刷新消失」四条，并在界面上用 `canvas.palette.hint` 一句话说明（§8.4 禁止暗示已保存）。

**放置栏不参与几何**：放置栏在页面布局层（CSS 两栏），不进世界坐标、不进 `layoutPreset`，也不改视口尺寸换算。

## 9 状态与空态

| 场景 | 呈现 |
|---|---|
| 无观测投影（未发起对话） | 5 张卡片照常渲染；阶段轨道全部「未开始」；连线全部 `idle`；不显示「暂无数据」遮罩 |
| 有投影 | 阶段条状态点随投影更新；卡片其余内容不变（仍是示例常量） |
| 投影只覆盖部分阶段 | 未出现的阶段取 `pending`；不推断、不补拉 |
| 用户删空画布 | 保留放置栏（可继续拖入）；视口空白但区带标签仍显示（区带是预设结构，不随卡片删除消失） |
| 放置栏拖入中 | 显示落点预览框（`--ant-color-primary` 虚线），松手生成卡片 |

**空画布不是空态**：W2 的画布没有「空状态插图 / 引导文案」；画布空只意味着用户删光了卡片，区带标签仍在，放置栏仍可用。
